## Summary

`setup-user-cursor.sh/.ps1` step 4 now fans out only user-level rules (manifest source `shared` or `dotprofile`) to `~/.cursor/rules`, and removes the `.mdc` of every `aitools` (project) or `retired` rule that the fan-out created. A user's own `.mdc` is never removed. Mission S3-H2-Cursor (HARNESS-2).

## Why

Commander decision 2026-10-22: Claude Code gets everything in `~/.aitools/rules`, Cursor gets user-level rules only (HARNESS Q1). The rules manifest from #100 (HARNESS Q2, approved) names each rule's source. Without this, the #87 fan-out loads aitools' project rules (17 always-apply) in every Cursor chat under `~`.

## Changes

- `scripts/setup-user-cursor.sh` / `.ps1`, step 4:
  - Reads `~/.aitools/rules/.aitools-rules-manifest` (`read_rules_manifest` / `Read-RulesManifest`). A valid line has a `*.md` name with no `/` or `\` and no `.bak.`, a known source, and is not a case-insensitive duplicate. Invalid lines are ignored with a warning.
  - Fans out only `shared` / `dotprofile` names (matched case-insensitively). A file in `~/.aitools/rules` not in the manifest is logged and not fanned out. A user-level name with no file is a warning.
  - **Recognising fan-out files:** the converter now writes an aitools-fanout marker as the line after the frontmatter: `<!-- aitools-fanout: generated by setup-user-cursor from ~/.aitools/rules/<name>; edit that rule, not this file -->` (`cursor_rule_is_fanout` / `Test-CursorFanoutRule`). A file from the #87 fan-out (no marker) counts as created by the fan-out when its content equals the conversion of the harness copy.
  - **Pruning:** for each `aitools` or `retired` name, a recognised `~/.cursor/rules/<stem>.mdc` is backed up (`<file>.bak.<ts>`, per file, not `backup_dir`) and removed. Each removal gets a `DETAIL|cursor rules|removed: <file>` row. Any other file of that name is kept, with an info line saying so. If the name maps to a file deployed this run (a case-only difference), the file is not touched. Dry run logs only.
  - **No manifest, or a first line other than `# aitools rules manifest v1`:** nothing is fanned out and nothing is removed. The step writes a WARN row (`no rules manifest` / `rules manifest not v1`) and the ACTION "Run aitools to rebuild ~/.aitools/rules and its manifest". An unreadable manifest is an ERROR row.
  - Row when nothing is fanned out: `N removed` or `n/a (no user-level rules)`.
  - The manifest itself is skipped silently. It is a dot file: the `.sh` glob never lists it, and the `.ps1` skips names starting with `.` before any log. The #100 follow-up note ("Ignoring non-rule file ... .aitools-rules-manifest") does not reproduce on main's `setup-user-cursor.ps1` (the `StartsWith(".")` skip comes first), and a test now asserts that neither script mentions it.
  - PS1: a name containing `[ ] * ?` is backed up with `Copy-Item -LiteralPath`. `Backup-File` in aitools-lib uses wildcard paths and reports success without making a copy (not fixed here: aitools-lib is outside this mission).
- `tests/rules-fanout-cursor/`:
  - The existing cases get manifest fixtures.
  - New cases: users (only shared/dotprofile fanned out; a #87-era `aitools` `.mdc` and a marked `retired` `.mdc` removed with backups; user files with an aitools or retired name kept; `*.bak.*` and the manifest silent), rerun, nomanifest, badheader, invalid lines plus case-insensitive names, onlyremove, a `[ ]` name, dryprune, and a missing source.
  - New `step4-driver.ps1` runs step 4 of the `.ps1` on pwsh 7 (OS guard bypassed, isolated `USERPROFILE`). Every manifest case compares the `.ps1` result with the `.sh` result: exit code, `~/.cursor/rules` tree (names and md5), and summary rows.
  - `convert-rule.ps1` takes an optional rule name (marker parity).
