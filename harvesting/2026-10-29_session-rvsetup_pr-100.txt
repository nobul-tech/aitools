## Contract change

Four changes to the shared contract, each for safety or determinism:

1. **Only a listed source retires.** The launch contract retired any name
   "absent from every source this run". A dotprofile that is not
   configured, not found, or not a git checkout would then retire, and
   delete, every user rule on that run (and `.claude/rules` if the repo
   listing failed). Now a name whose previous source was not listed this
   run keeps its previous line and its file.
2. **A retired name's file is removed on every run while it exists**, not
   only on the run that retires it. This makes a failed backup or removal
   self-healing, and keeps `~/.aitools/rules` consistent with the
   manifest. Each removal is backed up first; a failed backup leaves the
   file in place (log_error + ERROR row).
3. **Names are compared case-insensitively** (as the conflict check is):
   `Scratch.md` in the previous manifest and `scratch.md` in a source are
   the same rule. Without this, removing the "retired" `Scratch.md` on a
   case-insensitive file system would delete the live `scratch.md`.
4. **Added**: unknown header -> warning, nothing retired, rewritten;
   invalid lines (not `*.md`, `*.bak.*`, `/` or `\` in the name, unknown
   source) -> ignored with a warning (no path outside `~/.aitools/rules`
   is ever touched); dry run -> logged only.

## Contract

- File: `~/.aitools/rules/.aitools-rules-manifest` (no .md extension, so consumers that copy only *.md never copy it).
- Format: UTF-8, LF, first line `# aitools rules manifest v1`, then one line per rule: `<file name><TAB><source>`, source one of `shared` (aitools shared/rules), `aitools` (aitools .claude/rules), `dotprofile` (dotprofile claude/rules), `retired` (was in a previous manifest, no longer in any source). Lines sorted by file name (byte order). Only *.md file names; never *.bak.*.
- deploy-harness writes it on every run after the rules copy (temp file then move), recording the source that won (first source wins; duplicates already produce log_error + ERROR row).
- Retiring: a name present in the previous manifest (with a non-retired source) and absent from every source this run (names compared case-insensitively) becomes `retired`, but only when its previous source was listed this run; a name whose source was not listed (directory not found, not a git work tree, git ls-files failed, no dotprofile configured) keeps its previous line and file. While a name is `retired`, deploy-harness backs up and removes `~/.aitools/rules/<name>` whenever it exists (a failed backup leaves it: log_error + ERROR row), logs it, and keeps the `retired` line in later manifests until the name reappears in a source. With no previous manifest (first run) nothing is retired. A previous manifest with another first line: warning, nothing retired, rewritten. Invalid lines: ignored with a warning.
- Consumers: take every non-retired name they are entitled to; back up and remove their own deployed copy of every `retired` name (Cursor also removes names whose source is `aitools`).
- Manifest write failure: log_error + ERROR row, run continues.
