## Summary

An adopt into the dotprofile through the managed-file library (`deploy_managed_file` / `Deploy-ManagedFile` accept & adopt and merge & adopt, `review_json_fields` / `Review-JsonFields` field adopt) is now committed (that one file) and pushed by the library. Adopt targets outside the dotprofile (the aitools repo) stay working-tree changes, as before.

## Why

N-Q2 (dotprofile writes auto-commit and push) and M3-FINISH item 1 (commander 2026-10-22): "an adopt into the dotprofile through the library ... must commit and push it, like setup-user-claude's rules path already does. One shared lib helper; never commit unrelated changes (pathspec commit); push failure = WARN + ACTION." Rule: `.claude/rules/managed-file-deployment.md` "Adopt target". Before this PR the library said "never commits or pushes" and only setup-user-claude's rules loop committed, and only after merge & adopt.

## Contract

`dotprofile_commit_push FILE MESSAGE` (bash) / `Invoke-DotprofileCommitPush -File FILE -Message MESSAGE` (PS1)

- In the dotprofile = FILE's git top level equals the dotprofile's git top level. Dotprofile = `AITLIB_USER_REPO_PATH` / `$script:AitLibUserRepoPath` when the caller ran the resolver (set, even to `""`), else a quiet resolver call (no ERROR row).
- Pathspec commit: `git add -- FILE`, `git commit -m MESSAGE -- FILE`. Push: `GIT_TERMINAL_PROMPT=0`, ssh BatchMode unless `GIT_SSH_COMMAND` is set. git output -> deploy.log detail.
- Result global `AITLIB_DOTPROFILE_PUSH` / `$script:AitLibDotprofilePush`:
  - `committed-pushed`: ok line
  - `unchanged`: file matches HEAD; no commit, no push, no warning
  - `commit-failed`: warn + ACTION `commit and push <file> in <dotprofile>` (also when the dotprofile is not a git repository)
  - `push-failed`: warn + ACTION `git pull --rebase, then git push in <dotprofile>` (rejected / non-fast-forward / fetch first) or `run git push in <dotprofile>`
  - `not-dotprofile`: detail line only
- Always returns 0 (bash) / writes nothing to the output stream (PS1, it runs inside `Deploy-ManagedFile`). ACTIONs once per run. The deploy result stays `accept & adopt`.
- Adopt-path commit message: `Adopt <file name> from the deployed copy`.
