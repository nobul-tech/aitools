- **A-23** `scripts/setup-user-cursor.sh/.ps1`: on rc 3 the script now logs its own error (`log_error` / `LogError`) and writes `ERROR|cursor cli|not merged: dotprofile error`. Before, it wrote an info line and `ERROR|cursor cli|skipped (dotprofile error)`.
- **A-26 (cursor part)** `scripts/setup-user-cursor.sh/.ps1`: the cli-config dry run now writes a summary row in both languages. A dry run that would change the file writes `OK|cursor cli|dry-run: would update`, the same wording as the config writer. A dry run on an up-to-date file writes `OK|cursor cli|verified`. The .sh already wrote that row; the .ps1 wrote none.
- **A-24** `scripts/check-lib.sh/.ps1`: `resolve_config` / `ResolveConfig` now keep the resolver rc in `USER_REPO_RC` / `$script:UserRepoRc`. On a resolver error, `print_summary` / `PrintSummary` add one step: `0. Dotprofile resolution [WARN] resolver error (rc 3, see deploy.log) -- dotprofile steps reported 'not configured'`. That step is counted in the run summary and written to checks.log / checks.jsonl. Before, `check_log_init` reset the lib's error, so a broken dotprofile passed the check run. The check-*.sh/.ps1 callers are unchanged: they are outside this mission's files (see Follow-ups).

The .ps1 setup scripts run as guard-stripped copies in a temp `scripts/` copy, never the source. Each case gets its own temp HOME and stub rg/agent.
