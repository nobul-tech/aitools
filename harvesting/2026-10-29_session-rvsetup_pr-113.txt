## Summary

- The lib profile runner (`_aitlib_profile_run` / `Invoke-AitLibProfile`) accepts resolver output with a `result` line and no `via` line (what `register` and `migrate` print), and a bare value for `hostname` / `machine-id`.
- `aitools user init` (scripts/aitools, aitools.ps1) drops its private runners and uses the lib runner.
- User init passes `--no-machine` / `-NoMachine` to setup-user-config when it has concluded that this machine is not registered, so the writer adds no second machine-profile ERROR / ACTION.

## Why

M3-FINISH items 2 and 3 (commander): "The lib runner accepts 'result' lines (register/migrate print no 'via' line) so user init drops its private runner." The private runners existed only because the lib runner rewrote every exit 0/1 without a `via` line to 2. Item 2 consumes the writer flag from #98.

## Changes

Commit 1, e427e60 (lib + test-lib):
- Guard: exit 0/1 is trusted with a `via` or `result` line; for `hostname` / `machine-id` with a non-empty value. Anything else is still rewritten to 2 with an `error` line.
- A missing resolver: the runner still returns 1, and now also sets RC 2 with an `error` line naming it (the private runners' behaviour). Existing wrappers log their own message as before.
- A throw: RC 2 with an `error` line `aitools-profile CMD threw: MSG` (in-process PS, and the Git Bash pwsh branch).
- Git Bash branch: absolute values after `--profile`, `--out`, `--config` are converted with `cygpath -w`, as well as `--path` (what the private bash runner converted).
- The runner's temp-file removal is checked (`_aitlib_rm_tmp`, failure = detail line): the runner part of audit A-4.

Commit 2, 8967660 (user init + test-user-init):
- `ui_profile_run` / `Invoke-UiProfile` call the lib runner and copy its results (lib result-global contract); call sites unchanged.
- Deliberate differences from the private runners (review m1, m2): a failed temp-file removal is now a detail line, as in the lib, not a warning (a warning would promote every lib caller's OK rows, D-TS12); `AITOOLS_PROFILE_SH` / `AITOOLS_PROFILE_PS1` now override user init's resolver too, as for every lib caller (documented in both wrapper comments, commit 3).
- Flag: decided in the `machine_key` empty block after registration (scripts/aitools, aitools.ps1), not from an empty key at the writer call. The owner-"config" branch (registered, id undetectable) also empties the key and does not get the flag. The flag and `--machine-id` are never both passed.

## Contract (lib runner's accepted outputs)

| command | trusted when | else |
|---|---|---|
| `hostname`, `machine-id` | exit 0 and a non-empty value | rewritten to exit 2 + `error` line |
| every other command | exit 0 or 1 and a `via` or a `result` line (user-repo-path, resolve, exception-get, derive-config: `via`; register, migrate: `result`; exception-set: both) | rewritten to exit 2 + `error` line |
| any | exit 2, 3, 4 | passed through with the resolver's lines |
| resolver missing | runner returns 1, RC 2, `error` line naming it | |
| throw (PS) | RC 2, `error` line `aitools-profile CMD threw: MSG` | |

Case-by-case comparison with the removed private runners: S3-MF-Runner-plan.md section 1 (in this PR).
