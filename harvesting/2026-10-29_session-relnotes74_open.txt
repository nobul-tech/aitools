**`read_harness_manifest` / `Read-HarnessManifest`**
- KIND is `rules` or `skills`, case-sensitive.
- sh prints `rule<TAB>name<TAB>source` lines (the same first word for both kinds), `invalid<TAB><line, tabs as <TAB>>` lines, or `header-bad`.
- sh exit codes: 0 read (the output may be `header-bad`), 1 FILE missing, unreadable or a directory, 2 unknown KIND. The message is on stderr.
- ps returns `@{ Status = ok|header-bad; Rules = List of @{Name; Source}; Invalid = List[string] }`, with the key `Rules` for both kinds. It throws in both failure cases.

**`fanout_text_equal` / `Test-FanoutTextEqual`**
- 0: equal, ignoring trailing CR/LF.
- 1: they differ.
- 2: they cannot be compared: a file is missing, a directory or unreadable, or (sh) perl failed.
- Every 2 writes a detail line: `<fn>: cannot read <file>: <reason>`, or (sh) `fanout_text_equal: perl failed (exit N): <message>`.

**`fanout_dir_matches` / `Test-FanoutDirMatches`**
- 0 when TARGET is a real directory, every non-`*.bak.*` regular file under it exists as a regular file at the same path in CAND (a symlink to one counts) and is text-equal, and TARGET holds at least one such file.
- 1 in every other case:
  - TARGET or CAND is empty;
  - TARGET is missing, a file or a symlink;
  - TARGET holds no such file;
  - a file is missing, different or not regular in CAND;
  - anywhere under TARGET there is a non-regular entry: a symlink or reparse point (never followed), a FIFO, a socket, or a block or character device. These are rejected before any read.
- 2 when something cannot be read:
  - a directory that cannot be listed;
  - an entry that cannot be lstat'ed (a directory without search permission);
  - a file that cannot be read;
  - (sh) perl failed.
- `*.bak.*` base names are matched case-insensitively, empty subdirectories are ignored, and 2 wins over 1.
- Each reason is its own detail line: `<fn>: cannot list <dir>: <reason>` or `<fn>: cannot read <path>: <reason>`.

**`backup_dir` / `Backup-Dir`**
- Copies DIR to `DIR.bak.<UTC>`, or `DIR.bak.<UTC>-<n>` when that name is taken, and keeps the newest 5.
- Result variables, reset on every call:
  - `BACKUP_DIR_OK` / `$script:BackupDirOk`: true only when the copy exists.
  - `BACKUP_DIR_PATH` / `$script:BackupDirPath`: the copy's path.
  - `BACKUP_DIR_REASON` / `$script:BackupDirReason`: `no directory`, `no top-level *.md`, `cannot list` or `copy failed`.
- The skip rule (no top-level `*.md` means no backup) is kept and documented, because its two callers rely on it: the setup-user-claude rules dir and the setup-user-cursor rules dir. It now writes a detail line. The extension is compared case-insensitively in both shells, so `X.MD` counts. The old .ps1 (`-Filter`) already ignored case; the old .sh (`find -name`) did not.
- A copy that fails part-way is removed (sh: `chmod -R u+rwX` first; ps: ReadOnly attributes cleared). If the removal fails, the copy is renamed to `<dir>.bak.incomplete.<UTC>[-n]`, which the prune never matches. Either way it is logged.
- Symlinks inside the directory keep each shell's old behaviour. sh uses `cp -R`, which copies a link as a link (BSD and GNU, unchanged). ps copies the link's content, as `Copy-Item` did, so no Windows symlink privilege is needed. In ps a dangling link, or more than 64 levels (a loop), fails the copy.

3. `backup_dir` / `Backup-Dir` gain the result variables and literal-name pruning (PR #119 review finding 5). Behaviour changes for existing callers:

   - a warning when the directory cannot be listed (sh used to skip silently on a `find` error);

4. Skills manifest entries use the same first word `rule` (sh) and key `Rules` (ps) as rules, as section 3.3 states.
5. `deploy_managed_file` / `Deploy-ManagedFile` treat a dangling symlink destination (or a link loop) the same way in both shells.

6. `deploy_tracker_summary` / `Write-DeployTrackerSummary`: when every count is 0 (nothing recorded, or only preserved / skipped items), the text is `n/a (nothing to deploy)`, no longer `verified`.
