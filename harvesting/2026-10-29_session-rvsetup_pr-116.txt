## Summary

FIX-2 of M3-FINISH item 7. The installers' Step 5 and `aitools user init` now run their child scripts through the lib relay (`run_child_relayed` / `Invoke-ChildRelayed`), and the installers' private relay copies are gone. As a result:

- child warnings and errors are counted;
- every failed child gets an ERROR summary row;
- the children's lines reach deploy.jsonl.

An unwritable deploy.jsonl is one warning, and the run goes on. Step 3 failures get an ERROR row and skip Step 5. A missing `--alias` value is logged through the lib.

Audit findings: A-1, A-12, A-13, A-14, A-15, A-16, A-17, A-18.

**Branch:** `fix/mf-installer-relay` is stacked on #115 (`fix/mf-lib-relay`): PR A's head 4c55ec0, then a `--no-ff` merge of its review fixes 2ae798a. FIX-2's own commits are 1e44578, 7a16400 and ccccbd8.

## Changes

### A-1, A-18: installers (`scripts/aitools-install.sh` / `.ps1`)

- **Removed:** the private relay bodies and the JSONL globals (`LOG_JSONL`, `RUN_ID`, `HOST_NAME`; PS `$logJsonl`, `$runId`, `$hostName`, `$osName`).
- **Log override:** the `log` / `Log` override calls the lib's `jsonl_record` / `Write-JsonlRecord`.
- **Step 5:**
  - bash: `run_child_relayed --summary-tool "aitools config" "Step 5: setup-user-config.sh" ...`
  - PS: `Invoke-ChildRelayed "Step 5: setup-user-config.ps1" $Writer $WriterArgs "aitools config"`
  - A writer that dies before writing a row gets `ERROR|aitools config|script failed (exit N)`. A writer that wrote its own ERROR row gets no second one (#115's rule).
- **Kept as thin wrappers:** the installer block still has `jsonl_write`, `run_config_writer` and `Invoke-ConfigWriter`, because tests/profile/test-config.sh calls those names and another mission owns that file. They have no logic of their own (see Follow-ups). PS `Write-JsonlRecord` is now the lib's.
- **Run id:** both installers export `AITOOLS_RUN_ID` (6 random bytes as hex) when it is unset. The installer's records, its relayed children and any child that relays its own children (deploy-harness, #106) then share one run_id.

### A-16: lib (`scripts/aitools-lib.sh` / `.ps1`)

- The first failed write in `jsonl_record` / `Write-JsonlRecord` is one `log_warn`: `deploy.jsonl: cannot write <path> -- structured log records are skipped for the rest of this run`. Later records are skipped.
- The flag is set before the warning, so the installer's log override, which writes a record for every log line, cannot recurse.
- PS writes the exception text as a detail line, so the warning text matches bash.

### A-17: installer Step 3

- New helpers `resolve_repos_dir` / `Resolve-ReposDir`. A path that cannot be created gets ERROR `aitools config` `repos dir not created`; one that cannot be resolved gets `repos path not absolute`. Each is one error, and Step 5 is skipped with an info line.
- **Bug found by the new test:** in PS, `New-Item -ItemType Directory -Force -ErrorAction Stop` returned `$null` with no error when a parent was a file (pwsh 7, macOS; probe below). The old Step 3 carried on silently there. It now uses `[IO.Directory]::CreateDirectory` and then checks with `Test-Path -PathType Container`.

### A-12, A-13: user init (`scripts/aitools` / `aitools.ps1`)

- setup-user-config and setup-user-hooks run through the relay, with summary tools `aitools config` and `claude hooks`. PS runs both in-process.
- **Git Bash exception (review B M-1):** on Git Bash the writer is relayed through `pwsh -File`, but the hooks child runs directly. Its PowerShell review menus write their prompt with `[Console]::Write` and no newline, so the relay's line reader would hide the prompt until the user answered. The direct path keeps the relay's outcome: one error and the same row rule. On that path the hooks child's lines do not reach deploy.jsonl (follow-up).
- The fixed `ERROR|aitools config|setup-user-config failed` row is replaced by the relay rule: the writer's own ERROR row, or else the relay's `script failed (exit N)`.
- Exit 2 from hooks still returns 2 (D-TS13). The relay now records it as one error plus `ERROR|claude hooks|aborted (exit 2)` when the hook script wrote no row.
- A missing hooks script keeps its own `setup script missing` row.

### A-14: user init (bash)

- A stale run summary that cannot be removed is now a `log_warn`.

### A-15: `--alias` without a value

- **bash:** the error is queued while parsing and logged through the lib after `logging_init` (`--alias needs a value (aitools user init --alias <name>)`, exit 1). A value that starts with `-` counts as missing.
- **PS:** a missing value is a pwsh parameter-binding error raised before the script runs. That covers `--alias` as the last word, and `--alias` followed by one of the script's switches such as `--force` (corrected by review B m-1). It cannot be logged through the lib. A value that looks like an option (e.g. `-x`) gets the same error as bash after the lib loads.

## Assumptions

- **I-1 (deploy.jsonl definition, undecided; draft #162):** I used the audit's suggested answer: deploy.jsonl mirrors every child setup script run through the lib relay. Applied to installer Step 5 and to user init's two children.
  - The other installer steps (`validate_and_run` / `Invoke-ValidatedScript`: gh, tools, Step 21 deploy scripts) and the `aitools` sync deploy loop still run their children directly. They are not audit findings. Relaying them would also move every setup script's stdout off the terminal (tools' progress output, ordering against `/dev/tty` prompts) and change the installer's error rows. Listed under Follow-ups.
- **Warnings counted in user init:** the relay adds the children's warnings to user init's WARNINGS, as A-12 asks. user init writes no rows after its children and has no exit footer, so the count cannot be seen in the panel today. The tests check the relayed lines (console, deploy.jsonl), not the counter.
- **A user abort in the hooks review** is now an ERROR row (`aborted (exit 2)`) plus one counted error, as #115 decided and its review accepted. Before, it was only an info line.
