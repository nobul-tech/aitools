## Summary

FIX-1 of M3-FINISH item 7: the lib's child relay gives every failed child an ERROR summary row, and the machine-profile wrapper's "resolver missing" path writes its ACTION. Audit findings A-2, A-3 and the `run_child_relayed` part of A-4. No caller passes the new summary tool yet; the installers and user init switch to the relay in FIX-2 (stacked on this branch).

Branch `fix/mf-lib-relay` = origin/main + `--no-ff` merge of #113's head (`origin/fix/mf-lib-runner-result`, which contains #103 and #98), then one commit (4c55ec0).

## Why

- **A-3 (medium):** `run_child_relayed` / `Invoke-ChildRelayed` logged one error for a child that exited non-zero but wrote no summary row. Only a PS throw with SUMMARYTOOL got a row, and bash had no such argument. A child that died before its own `write_summary` (a `set -e` abort, exit 127, a pwsh parse error) disappeared from the end-of-run panel (script-standards-detail "Summary coverage rule").
- **A-2 (low):** `resolve_machine_profile` / `Resolve-MachineProfile` "resolver missing" wrote ERROR without an ACTION; every other failure path of the four wrappers writes one.
- **A-4, rest (low):** `rm -f "$rcf"` in `run_child_relayed` was unchecked. The profile-runner part shipped in #113 (`_aitlib_rm_tmp`).

## Changes

**A-3: `scripts/aitools-lib.sh` / `.ps1`, relay section**
- `run_child_relayed [--summary-tool TOOL] LABEL CMD [ARGS]`. The new optional leading flag matches `Invoke-ChildRelayed`'s 4th parameter. Calls without it behave as before.
- With a tool, a failed child that wrote **no ERROR row of its own** gets one. The rows, by case:

  | Case | Row (bash and PS) |
  |---|---|
  | non-zero exit | `ERROR\|TOOL\|script failed (exit N)` |
  | exit 2 | `aborted (exit 2)` (D-TS13) |
  | error lines with exit 0 | `logged errors (exit 0)` |
  | no command | `not run (no command)` |
  | mktemp failed (bash) | `not run (mktemp failed)` |
  | throw or parse error (PS) | `script failed (exception)` |

- The relay counts the ERROR rows in `AITOOLS_SUMMARY_FILE` before and after the child. Helpers: `_aitlib_summary_errors` / `Get-AitLibSummaryErrorCount` and `_aitlib_child_row` / `Write-AitLibChildRow`. An unreadable summary counts as 0 and is logged as a detail line.
- PS: an empty SCRIPT is now `not run (no command given)`, as in bash. Before, it was a throw with the "exception" row.
- Counters are unchanged: one `log_error` / `LogError` for a failed child; child error lines are still not added to ERRORS.

**A-2: same files, wrapper section**
- `resolve_machine_profile` / `Resolve-MachineProfile` "resolver missing" now writes ACTION `see deploy.log -- the dotprofile could not be resolved`. The text is the dotprofile wrapper's, so a run with both wrappers failing gets one ACTION (`_aitlib_action_once`).

**A-4 (rest): bash lib**
- `run_child_relayed` removes its exit-code file with `_aitlib_rm_tmp FILE LABEL`. A failed removal is a detail line naming the step; a warning would promote the parent's OK rows.
- `_aitlib_rm_tmp` takes an optional WHO (default `aitools-profile`, so #113's messages are unchanged).

**Tests: `tests/profile/test-lib.sh`**
- Every relay case now checks the summary rows.
- New relay cases: crash before any row (bash `false` under `set -e`, PS exit 1), exit 127, abort (exit 2), error lines with exit 0, PS throw, PS parse error, no summary tool, no command with a tool. A child that wrote its own row gets no second one.
- A-4 cases with `mktemp` stubs on PATH (macOS `mktemp` ignores TMPDIR): mktemp fails; the exit-code file cannot be removed (detail line, nothing else changes).
- A-2: `rmp-missing`, and `urp-rmp-missing` (one ACTION for both wrappers).

## Assumptions

- **Dedupe rule (design choice):** the relay adds a row only when the child wrote no ERROR row during its run, for any tool. Without it, every well-behaved failing child (log_error + ERROR row + exit 1) would show two ERROR rows. A-3's gap is the child that wrote none. If the commander wants "always one relay row", it is a one-line change in each helper.
- **Exit 2 detail is `aborted (exit 2)`**, not "failed", per D-TS13 (bare exit 2 = user abort). It is still an ERROR row and one counted error, as the installers count any non-zero exit today (reference/managed-file-deployment.md "[x]abort").
- **deploy.jsonl scope (I-1 / draft #162, undecided):** unchanged here. FIX-2 uses the audit's suggested answer.
