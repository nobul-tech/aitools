## Summary

Fixes S3-MF-Audit findings A-19, A-20, A-25 and the claude part of A-26 in `scripts/setup-user-claude.sh/.ps1` and `scripts/build-deploy.sh`. Adds a new test suite, `tests/claude-mdm/test-claude-mdm.sh`, and runs it in CI.

## Why

These come from S3-MF-Audit (PR #104), M3-FINISH item 7. I checked each finding in the code before fixing it. All four were confirmed and none was rejected:

- **A-25**: setup-user-claude.sh ran `scutil`/`uname` itself (old lines 93-109), and the .ps1 read `COMPUTERNAME` (old lines 171-175). The lib already exposes `AITLIB_MACHINE_HOSTNAME` / `$script:AitLibMachineHostname`. The resolver puts `hostname` in every resolve result, including rc 1.
- **A-26**: the dry-run branch (sh 216-238, ps1 230-254) wrote no summary row.
- **A-19**: `Remove-AitoolsEmbed` only ran before the exit footer. On macOS, the generated .ps1 OS-guard exit left `aitools-embed-*` in TMPDIR, and run in-process (`& script`) it left `AITOOLS_PROFILE_PS1` set. The new test reproduces both on the unfixed code. A probe showed pwsh 7 runs `finally` on `exit N` and keeps the exit code.
- **A-20**: blog_warn/blog_error always printed ANSI codes. The child resolver's console went to build-deploy's stderr, and the entry points append that stderr to deploy.log (`aitools:2055`, `aitools.ps1:2004-2009`). The child's own `logging_init` had already written those lines to deploy.log, so they appeared twice. The new test reproduces both.

## Changes

- **A-25** (`setup-user-claude.sh/.ps1`): the footer hostname is now `AITLIB_MACHINE_HOSTNAME` / `$script:AitLibMachineHostname`, or "unknown" when it is empty. The scripts' own hostname detection is removed, so there is one P-Q5 source.
- **A-26, claude part** (`setup-user-claude.sh/.ps1`): a dry run now writes one row: `OK|claude.md|dry-run: would create`, `OK|claude.md|verified` or `OK|claude.md|dry-run: would update`. This is the config writer's wording.
  - The comparison now works the way `deploy_managed_file` / `Deploy-ManagedFile` compares: trailing newlines removed, case-sensitive.
  - Before, the .ps1 compared `Get-Content -Raw` output, which keeps its trailing newline, using `-eq`. So an up-to-date CLAUDE.md read as "differs", and the new row would have been wrong.
  - An unreadable CLAUDE.md is now a log_warn / LogWarn in both languages.
- **A-19** (`build-deploy.sh`): the PowerShell embed block now ends with `try {`.
  - The three generated .ps1 files that embed the resolver (setup-user-claude, -cursor, -settings) end with `} finally { Remove-AitoolsEmbed }` after their exit footer.
  - `Remove-AitoolsEmbed` now runs only once (a flag). The call before the footer still counts a failed removal as a warning, and the call in `finally` does nothing after it.
  - A post-build check fails the build if a resolver-embedding .ps1 does not end with the finally line, or if another .ps1 has that line.
- **A-20** (`build-deploy.sh`):
  - blog_warn/blog_error use colour only when stderr is a terminal.
  - The standalone child resolver's console copy goes only to a terminal, otherwise to /dev/null. Its lines are already in deploy.log, and its stderr is kept.
  - The entry points are unchanged: they belong to S3-MF-Runner.
- **Port (deploy-paths.md)**: setup-user-claude is a pure extract in build-deploy, so the A-25/A-26 code reaches deploy/ through the build. I checked the generated output.
- **Tests**: new `tests/claude-mdm/test-claude-mdm.sh` with 32 checks:
  - A-25 and A-26 on the dev path, .sh and .ps1, with dry-run row parity between them.
  - The build-deploy port, A-19 static checks and the A-19 runtime on pwsh (OS-guard exit, in-process run, full run).
  - Smoke runs of the generated MDM .sh.
  - A-20 with stderr not a terminal, and on a pty.
  - The resolver hostname is stubbed through the lib's `AITOOLS_PROFILE_SH` / `AITOOLS_PROFILE_PS1` override.
  - CI (`.github/workflows/check.yml`) runs it on macOS (bash 5 and /bin/bash 3.2) and Linux.
