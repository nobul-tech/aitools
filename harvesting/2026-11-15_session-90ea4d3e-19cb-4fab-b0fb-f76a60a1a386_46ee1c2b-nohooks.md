## 1. Python troubleshooting

**Your real Terminal is fine.** Interactive login zsh resolves:
```
command -v python3  →  /Users/new-jose/.local/bin/python3  →  Python 3.14.6 (uv shim) ✓
```
The uv shim exists and is correct (`~/.local/bin/python3` → `~/.local/share/uv/python/cpython-3.14.../python3.14`). Interactively, `.local/bin` sits **before** `/opt/homebrew/bin`, so the uv interpreter wins. Python already works flawlessly when *you* type it.

**The install warning is a false alarm — and its remediation is wrong.** `aitools install` (and Claude Code's shell, and any hook/cron/MDM context) runs under a **different PATH** where `/opt/homebrew/bin` comes *first*:

| Context | `python3` resolves to |
|---------|----------------------|
| Interactive Terminal (login zsh) | `~/.local/bin/python3` → uv 3.14.6 ✓ |
| Non-interactive (install, hooks, Claude Code, cron) | `/opt/homebrew/bin/python3` → brew `python@3.14` 3.14.6 ✗ |

Why the split: the `.local/bin` prepend lives **only in `.zshrc`** (interactive), not `.zprofile` (login) — and anything that re-runs `brew shellenv` after it pushes `/opt/homebrew/bin` back to the front. `setup-python.sh:67-70` then sees brew's python and prints:
> `Ensure uv's bin dir (~/.local/bin) precedes /usr/bin in PATH`

That advice is **doubly wrong**: (a) `.local/bin` is already before `/usr/bin`, and (b) the actual shadow is `/opt/homebrew/bin`, which the message never mentions. You can't fix it by following it.

**Is it actually breaking anything?** Latently, not yet — brew's python is *also* 3.14.6 and the harness's python scripts (`ait-harvest.py`, dashboard, relay sync) are stdlib-only, so they run under either. The real problems are: (1) the design intent ("uv is the single Python") is silently violated in exactly the non-interactive contexts the harness relies on; (2) `uv pip`/`uv tool` packages install into the uv interpreter, so any future non-stdlib hook script would not see them; (3) the misleading, unactionable install noise on every run.

Two incidental findings from the probe:
- **`.zprofile:7` errors on every shell init** — `eval "$(/usr/local/bin/brew shellenv)"` fails (`no such file or directory: /usr/local/bin/brew`); there's no Intel Homebrew on this Apple Silicon Mac. Harmless but noisy; should be guarded or removed.
- Homebrew's `python@3.14` has **no dependents** (`brew uses --installed python@3.14` is empty) — so it's a direct/leftover install, not pulled in transitively. Removing it is *possible* but it's the wrong fix (brew could reinstall it; doesn't help the ordering principle).

- **A. Own the PATH ordering in login + non-interactive contexts** (the real fix).
