# aitools

**Intent**: **Purpose**: Orient every agent to aitools — Jose's central hub for
managing and leveraging AI tooling (CLI tools, Claude Code, Cursor, MCP servers)
consistently across all his repositories and machines. **Scope**: What aitools is,
how the harness is organized, and the operating discipline every session follows.
NOT tool install/config detail (`/tool-registry` skill). NOT the governance rules
themselves (`.claude/rules/`). NOT the failure-mode work that seeded the harness
(`reference/do-what-feels-right.md`). **Audience**: Every agent working in the
aitools repo, every session.

## What aitools is

aitools is the commander's hub for AI tooling — one place to install, configure, and
keep aligned the tools he leverages across every repo and both machines (Windows 11,
macOS): CLI tools, Claude Code, Cursor, MCP servers, hooks, skills, and the rules
that govern them. `aitools install` deploys that configuration to a machine; the
harness keeps it consistent so a session in any repo, on either machine, inherits the
same capabilities.

Under the hood it is a self-learning, provenance-aware system: each session can feed
operational learning back into the harness through various means, including handoff documents,
updates to skills, hooks, rules, reference files, registries and other artifacts such as
running estimates, briefings and after action reports, updates to
CLAUDE.md files, deployed on the local machine and adopted through "aitools"/"aitools install"
so they are tracked by the repo and the project and so the next session starts
sharper. Tokens are cheap; the commander's time is the scarce resource. Use your
context fully.

## How the harness is organized

- `.claude/rules/` — behavioral rules, always in context. Check them before assuming.
- `shared/` — source for user-level configs (skills, hooks, claude-shared) that
  `aitools install` deploys to `~/.claude/` and `~/.cursor/`.
- `scripts/` — the `aitools` CLI, `hh`, setup scripts, checks, `build-deploy.sh`.
- `tests/` — unit tests run in CI (`tests/logging/`: the shared logging framework).
- `deploy/` — generated by `build-deploy.sh`; ephemeral, reset on each `aitools` run.
- `reference/` — implementation detail and the origins behind the rules.
- `.aitools/channel/` — the relay and carry-forward operational learning.

When you delegate, the delegation duty applies (`/delegate` skill; user rule
`delegation.md`): seven prompt elements, including D-DEL1 — the delegate names
every `*.md` file it writes with its own name as a prefix (`S2-report.md`).

## The process (every prompt)

1. Parse for high-impact words
2. Check against this conversation
3. Check against files in context
4. Use disciplined initiative to resolve what you can
5. Surface only what you can't resolve
6. Batch clarifications
7. Verify your output against orders and vocabulary before sending

Disciplined initiative means deviating from process to accomplish the mission — not
appearing to know what you don't know.
