# S2-Layout-C adversarial review of the S2-Layout draft (HEAD 04cbdf0; the draft used 51a34d8, and 4 commits have landed since)

## Missed evidence
- E1. **The last path move is still broken, and nothing caught it.** b504c43 created `registries/`. Stale `reference/*.json` paths remain in: `shared/hooks/tool-ops-session-audit.sh:23-26`, which silently `exit 0` at :29, so the SessionEnd tool-ops audit has never run since then; `scripts/check-post-push.ps1:268,520`, where Windows step 21 SKIPs while the bash version at :448 was fixed; the skills audit, frameworks, glossary and incident (incident #84); and `shared/skills/intent-audit:131-135` and `optimize-plan:34`. A move about 9x larger, with no path-reference check, will repeat this, mostly on Windows.
- E2. **Rename hazard in live shell profiles.** `aitools-install.sh:614-628` writes an absolute `source ".../aitools/shared/shell/aliases.sh"`. It only adds that line when the marker is missing (:627) and never rewrites the path. Live examples: `~/.bashrc:3` and `~/.bash_profile:14`. After `shared/`->`user/`, every macOS/Linux machine prints a source error on each shell start, `cc`/`ccr`/`ccs` disappear, and re-running install does not fix it. PS1 does rewrite the line (`aitools-install.ps1:572-586`). The draft's "byte-diff of build-deploy output" check cannot see this.
- E3. **The other hardcoded `shared` paths the draft did not list.** PS1 builds it with `Join-Path ... "shared"` and backslashes: `aitools.ps1:1120`, `setup-user-hooks.ps1:46-185`, `setup-user-skills.ps1:36`, `check-post-push.ps1:177,360,740,955`, `aitools-install.ps1:528`. Live count: 89 files outside plans/rfcs/.aitools/harvesting/deploy.
- E4. **"user" is already taken.** In the glossary, `user` means "Deployed to ~/" (`registries/glossary.json` facets.scopeModifiers). "User repo"/`userRepoPath` means the dotprofile and appears more than 250 times across scripts, reference and rules (`reference/user-repo.md`: 18). A folder named `aitools/user/` next to the "user repo" (`aitools-nobul-jose/claude/`) adds a third meaning, which works against L4.
- E5. **Dotprofile shadowing already causes incidents.** `setup-user-skills.sh:93` says "dotprofile wins over shared". The build-deploy adopt step copies skills into `dotprofile/claude/skills` (`build-deploy.sh:1086-1090`). Incident #80 is the same pattern for hooks. The draft's rule "dotprofile claude/rules/ wins on same name" repeats that shadow on purpose.
- E6. **The resolver precedent does not exist yet.** No hook reads `config.json repoPath`. `tool-ops-session-audit.sh` uses `AITOOLS_REPO_PATH` and falls back to `~/repos/aitools`. `harvest-session.sh:51` hardcodes `~/repos/aitools`. `AITOOLS_REPO_PATH` is not set anywhere (settings.json, the shell profiles and setup-user-shell.sh all show it unset). The `~/repos/aitools` fallback is also wrong in the web environment, where repoPath is `/home/user/nobul-jose/repos/aitools` (dotprofile `environments/claude-code-web/CLAUDE.md:27`). It may be wrong on Windows too, because `cross-platform.md` says `C:\repos\`, which conflicts with CLAUDE.md's `%USERPROFILE%\repos`.
- E7. **Cloud sessions already depend on nested discovery.** Per code.claude.com/docs/en/skills (fetched 2026-10-20), nested `<subdir>/.claude/skills` loads "once Claude works on files there". The web session cwd is `/home/user` (env CLAUDE.md:9), so aitools project skills there already load lazily or not at all. The draft's premise that moving them loses cloud coverage overstates what we have today. The same page says personal skills load "not [in] Cowork or cloud sessions", but the `claude.ai account` channel does load there. It is unknown whether files that `aitools install` writes to `/root/.claude/skills` inside the container load. That needs a 5-minute test.
- E8. `registries/incidents.json` is 2027 lines, which is more than Read's 2000-line default. Telling a skill in prose to "read it, note the highest ID" can miss the newest IDs, which leads to duplicate IDs. A prose resolver multiplies this problem across machines.
- E9. `incident-governance.md` "Hook specifications" describes a PreToolUse agent hook on incidents.json and a SubagentStart cache. Neither exists in `shared/hooks/hooks-manifest.json:9-26`. Pre-commit step 16 (`check-pre-commit.sh:339`) scans only `.claude/rules/` and `CLAUDE.md`, so the proposed `user/rules/` would not be audited for bypasses.

## Flaws
- F1. **PR1 (the rename) comes first, but it gives no capability and carries most of the risk** (E2, E3). It also does not fix the `.claude/skills` name collision the draft diagnoses, because that name is tool-mandated.
- F2. **The prose resolver is not reliable.** It depends on the model doing env -> JSON -> exists checks. Concrete problems: Windows paths in config.json; subagents in other repos can Read but not Glob/Grep outside cwd (`aitool-ops/SKILL.md:184-197`); E8. "Writes only when cwd is the clone" fails wherever PRs are actually made, because feature work happens in worktrees (env CLAUDE.md:29,35; `.claude/worktrees/`). The rule has to be "cwd is a worktree of repoPath" (git common-dir).
- F3. **The snapshot needs its own deployment type.** `~/.aitools/registries/` (286 KB, incidents.json alone 167 KB, embedded into MDM scripts) is a new deployment type. Under `managed-file-deployment.md` "Updating this table" that triggers 4 protected-file updates and menu/return-value contracts, unless it is declared a sole-owner overwrite copy (`config-file-safety.md`, "Overwrite exceptions"). The draft names neither option.
- F4. **The draft deviates from L3 without asking.** It keeps audit and governed-data at project level, which splits 7/2 and keeps a project skills folder alive for 2 skills. That is the ambiguity L4 is meant to remove. Moving all 9 leaves `.claude/skills/` empty, so the rule becomes "all skills live in one folder". audit has `disable-model-invocation: true` (`audit/SKILL.md:4`), so moving it costs nothing.
- F5. **"Splitting breaks atomicity" only holds inside the moves.** The rename and the moves are independent. One atomic PR of about 89 renames plus 9 moves plus resolver code plus a new deploy type plus rules goes against UCI "smaller batches" and `plan-execution.md` (fresh sub-agent per batch, verification between batches).
- F6. **The retirement scope is undercounted.** `/aitool-ops` is cited in `shared/skills/delegate/SKILL.md:143,163,217`, `aitool-continue/SKILL.md:557-558` and dotprofile `claude/rules/delegation.md:10,132`, as well as `.claude/rules/aitool-{ops,eval}.md` and incidents.json. Retiring it is a cross-repo edit, and delegation.md is protected and commander-owned.

## Alternative design (S2-Layout-C)
- Keep `shared/` and make the level explicit without renaming it. Add `shared/README.md` ("everything here deploys to ~/; nothing here is project-level"). Fix the glossary so `shared` means "user-level source" (a single scope axis). Add a check that fails when the same name exists in `shared/`, `.claude/` and dotprofile `claude/`. That covers E5 and gives L4 at about 5% of the churn. Defer `user/` and reconsider it only if the confusion persists. If you do rename, pick a name that does not collide with "user repo" (for example `home/`). Ship it as its own PR with an rc-path rewrite in the installer (E2), plus PS1, CI and githook updates.
- PR-a, an enabler that is needed regardless: a path-reference check (every backticked repo path in skills, hooks and scripts must exist) and a fix for the E1 stale paths. It closes #84 and catches regressions in later PRs.
- PR-b, the moves: all 9 skills `git mv` into `shared/skills` (L3), registries into `shared/registries`, and resolver **code**, not prose. That means `~/.aitools/bin/aitools-registry.py {path|get|next-id|validate}`, deployed the same way as `harness-db.py` (`harness-db-sessionstart.sh:64`). It reads config.json repoPath, accepts a worktree of the repo, falls back to a sole-owner-overwrite snapshot with `.source.json`, and prints "unavailable" if nothing is found. The skills call it, which also fixes E8. Fix the hooks' `~/repos/aitools` fallback in the same PR (E6).
- PR-c: retire the reference cards. Update their citers (F6), including a delegation.md edit presented to the commander.
- Cloud: run the E7 test first. If container-written personal skills load, add `aitools install` (or just the skills step) to the environment Setup script. If they do not load, the fallback is the claude.ai account skill channel for the 4 L1 skills. Accept the gap in the meantime: today's coverage is already lazy (E7).

## Concessions
L1 to L3 moves, `git mv` with no dual copies, the rule that level comes from the folder and never from the prefix, a same-name check, writes outside the clone becoming gh issues (RFC 0001), and rejecting the plugin option C (namespacing, and plugins do not load in cloud sessions). These hold. Approving the spec up front fits `sources-of-truth.md` and D-DEL4 (`delegation.md:22,73-82`). Approving through a draft PR would mean writing protected files before approval.
