Read with S3-Merge2-brief.md (same folder). Your prompt names your role, PR
number <n>, branch <b> and worktree <w>. Scratch for every role:
`<w>/.scratch/session-m2<role-initial><n>/` (Prep: `session-m2p<n>`, ReVerify:
`session-m2r<n>`, Land: `session-m2l<n>`, Check: `session-m2c<n>`), with any

## Role: Prep (bring PR <n> up to date and green; do NOT merge the PR)
1. `git -C <w> fetch origin`; `git -C <w> status --short` and `git -C <w> log --oneline -3`. The worktree must be on <b>, clean, and its HEAD equal to origin/<b> (`git -C <w> rev-parse HEAD` vs `origin/<b>`). If it has unpushed commits or uncommitted changes, do not discard them: record them and stop with a BLOCKER (unless your prompt says otherwise).
2. Read the reviewer verdict(s) for PR <n> (files `S3-Merge2-Review*-verdict*.md` in the mission folder that name PR <n>, and the PR comments: `gh pr view <n> -R nobul-tech/aitools --comments`). Every BLOCKING finding must be fixed in this step; non-blocking findings your prompt lists as "fix" are fixed too.
3. `git -C <w> merge --no-ff origin/main` (never rebase). Resolve conflicts keeping both sides' intent; for files moved/deleted on main (#128, #129) follow main's new layout and re-apply the PR's change there; never drop a test. Commit the merge with `git -C <w> commit -F <msg file>`; the message names the conflicts and resolutions and quotes the commander's 2026-10-26 order "merge commits, mission merges, in the correct order, and checks after each step".
4. Fix commits (review findings, CI fixes): code bug = fix + test. Each its own commit with a body: what, why (finding id), how verified, not run, `(tested: macOS)`, and the attribution line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
5. Verify: run every suite the PR touches (and every suite under tests/ whose subject files the merge changed) under an isolated HOME with absolute paths, under /bin/bash (3.2) as well as bash; `bash -n` and the pwsh parser on every touched .sh/.ps1; `bash /Users/new-jose/repos/aitools/scripts/check-pre-commit.sh` and `check-pre-push.sh` run from <w> (use `bash <w>/scripts/check-pre-commit.sh` with cwd semantics via a scratch script that cd's into <w>). Known failures: pre-commit step 6, pre-push step 7 — record, do not block.
6. `git -C <w> push origin <b>` (never force). Then wait for CI on the new head: `gh pr checks <n> -R nobul-tech/aitools --watch` (or a Monitor/until-loop scratch script). FIX ISSUES WHEN THEY ARISE (commander, 2026-10-28: "give it explicit instructions to fix issues when they arise"): if a check fails, `gh run view <id> -R nobul-tech/aitools --log-failed`, fix the cause on <b> (code bug: fix + test; flaky/infra: re-run once with `gh run rerun <id> --failed` and record), push, re-check. Up to 3 fix rounds, then STOP and report BLOCKER with the evidence.
7. Done when every check is SUCCESS (CodeQL NEUTRAL/SKIPPED ok) and `gh pr view <n> -R nobul-tech/aitools --json mergeStateStatus,headRefOid,baseRefName` shows CLEAN, base main. Post a PR comment (`gh pr comment ... --body-file`) summarising the merge-main and fixes, with the final head SHA. Do NOT run `gh pr merge`.
Report: final head SHA, commits added (SHA + subject), conflicts and resolutions, findings fixed, verification results, CI run ids, mergeStateStatus.

## Role: ReVerify (independent re-review of PR <n>'s FINAL head)
You did not write the change. Read the earlier verdict(s) for PR <n> and the PR comments. Review exactly the commits added since the reviewed head (`git diff <reviewed SHA> origin/<b>` and the merge commit's conflict resolutions: `git show --remerge-diff <merge sha>` if available, else compare against both parents). Check: blocking findings really fixed; conflict resolutions kept both sides' intent, followed main's layout, dropped no test; no unrelated changes. Run the touched suites in a NEW detached worktree `/Users/new-jose/repos/aitools/.claude/worktrees/m2-rr<n>` at origin/<b> under an isolated HOME (never remove the worktree). Confirm CI green and CLEAN. Write `S3-Merge2-ReVerify<n>-verdict.md` (first line `VERDICT: MERGEABLE` or `VERDICT: BLOCKING`, the head SHA) and post it with `gh pr comment <n> -R nobul-tech/aitools --body-file <file>`, citing the commander's 2026-10-28 order "learn from past mistakess". Report the verdict, head SHA, comment URL.

## Role: Land (merge PR <n> and check main)
Commander's authority for this merge (quote in the merge comment): 2026-10-26 "merge commits, mission merges, in the correct order, and checks after each step"; "it should not merge PRs until all github CI/CD checks/auto merge status are green. it should check its work after each merge." and 2026-10-28 "launch a mission to serve as an orchestrator and merge open prs in the correct order."
1. Pre-merge gate (all must hold, else STOP, no merge): `gh pr view <n> -R nobul-tech/aitools --json headRefOid,baseRefName,mergeStateStatus,statusCheckRollup`: base main; mergeStateStatus CLEAN; every check SUCCESS (CodeQL NEUTRAL/SKIPPED ok); headRefOid equals the SHA named in the latest ReVerify (or Review) verdict comment marked MERGEABLE (your prompt gives the expected SHA and the verdict comment URL).
2. Post a PR comment quoting the commander's order above and linking the verdict comment URL. Then `gh pr merge <n> -R nobul-tech/aitools --merge --match-head-commit <sha>` (merge commit only; never --squash/--rebase; do not pass --delete-branch). If denied: `WRITE_BLOCKED` and stop.
3. Record the merge commit SHA (`gh pr view <n> --json mergeCommit,state`). Check it has two parents (`git -C /Users/new-jose/repos/aitools fetch origin` then `git -C /Users/new-jose/repos/aitools rev-list --parents -n 1 <sha>`).
4. Wait for main's CI on that SHA: `gh run list -R nobul-tech/aitools --branch main --limit 5 --json databaseId,headSha,status,conclusion,workflowName`, then `gh run watch <id> -R nobul-tech/aitools --exit-status` for each run on that SHA. CodeQL NEUTRAL/SKIPPED ok.
5. Run the PR's touched suites against main in a NEW throwaway detached worktree `/Users/new-jose/repos/aitools/.claude/worktrees/m2-main<n>` at the merge SHA, isolated HOME (never remove it).
6. If main is red: do not proceed; report BLOCKER with run id and `--log-failed` excerpt (the orchestrator launches a fix-forward).
Do NOT pull into the main checkout. Report: merge SHA, parents, main CI run ids + conclusions, suite results.

## Role: Check (independent verification of a landed merge)
Confirm for PR <n> and merge SHA <m>: PR state MERGED with mergeCommit <m>; <m> is a true merge commit (two parents: previous main tip and the PR head SHA your prompt names) — not squash/rebase; `git diff <m>^1 <m> --stat` equals the PR's net change (`git diff <m>^1 <PR head>` after merge-base semantics: compare `git diff <m>^1 <m>` with `git diff <m>^1...<PR head>`-style expectations; explain any difference); no unrelated files; main CI for <m> green (run ids). Write `S3-Merge2-Check<n>-verdict.md` (first line `VERIFIED` or `NOT VERIFIED`) and report it. Read-only: no pushes, no comments required (optional `gh pr comment` with the verdict is allowed).
