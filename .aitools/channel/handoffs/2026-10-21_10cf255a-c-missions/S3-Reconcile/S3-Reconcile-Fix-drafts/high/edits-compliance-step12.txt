FX-NEW-1 (medium; found by S3-Reconcile-Fix while testing FX-1): bash
check-script-compliance.sh filters comments with `grep -n ... | grep -v '^\s*#'`.
`-n` prefixes "NNN:", so the comment filter never matches, at all six sites
(steps 3, 6, 7, 11, 12 twice). Visible today in step 12: a comment naming
write_summary / Write-Summary counts as an invalid category, so on origin/main
post-push step 23 FAILs with "2 invalid: setup-user-config.sh(1)
setup-user-config.ps1(1)" (the "# --- 3. One ACTION ... write_summary" comment;
throwaway-clone run 2026-10-26). The PowerShell twin tests each line without a
prefix and is correct. Fix: match the comment after the "NNN:" prefix (steps 3
and 11 need the line numbers, so -n stays). Excluding comments only removes
matches, so no check can newly fail.

@@@FILE scripts/check-script-compliance.sh step 3 comment filter
@@@OLD
    exit_lines=$(grep -n 'exit 1' "$f" 2>/dev/null | grep -v '^\s*#' | grep -v 'esac' || true)
@@@NEW
    # grep -n prefixes "NNN:"; the comment filter matches after it.
    exit_lines=$(grep -n 'exit 1' "$f" 2>/dev/null | grep -vE '^[0-9]+:[[:space:]]*#' | grep -v 'esac' || true)
@@@END
