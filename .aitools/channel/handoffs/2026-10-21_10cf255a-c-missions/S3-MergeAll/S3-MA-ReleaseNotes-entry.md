## v0.74.0 -- Deployed harness in ~/.aitools, machine profiles keyed by machine id, managed files with SOURCE as the source of truth, logging conformance (2026-10-27)

Covers 2026-10-03 to 2026-10-27: PRs #35-#131 and the commits made directly on main, including the untagged v0.73.3 (PR #35). Four lines of work land together:

- **Deployed harness.** A new `deploy-harness` builds `~/.aitools/{reference,registries,hooks,rules,skills,bin}` from the aitools repo and the dotprofile, records each rule's source in a manifest, retires removed rules, and runs in every `aitools install` and every `aitools` sync. Cursor gets the rules as `~/.cursor/rules/*.mdc`. The MDM `deploy/` gets a self-contained copy with a payload file.
- **Machine profiles (M3).** One native resolver (`aitools-profile.sh/.ps1`, no node) answers "which dotprofile" and "which machine profile is this machine". Profiles are keyed by the raw machine id, `aitools user init` registers the machine, `setup-user-config` is the only writer of `~/.aitools/config.json` (v3), and the generated `deploy/` resolves the profile on the target machine instead of baking one machine's values in at build time.
- **Managed files.** SOURCE is the source of truth: one review menu, adopt and merge write the repo in the same step (and commit and push when the target is in the dotprofile), JSON is reviewed field by field, every write is backed up, validated and restored on failure. Deploy state and the silent auto-merge are gone.
- **Logging conformance** (epic #21) across both installers, both entry points and 14 setup-script pairs, plus an audit-and-fix round (findings A-1..A-26) on the M3 code.
