**Intent**: **Purpose**: Define the dotprofile repo -- where it lives on every platform,
the schema of its `profile.json`, the schema of the per-machine `~/.aitools/config.json`
derived from it, and the order in which aitools resolves "which dotprofile" and "which
machine profile". **Scope**: Location convention, directory layout, profile.json and
config.json schemas, resolution order and failure behaviour, writers of each file,
template tokens, session-archive layout. NOT the settings.json sync algorithm
(`@reference/managed-file-deployment.md`). NOT tool exception semantics
(`@reference/tool-support-decision-tree.md` section 8; this file fixes only their
storage shape). NOT hook lifecycle.
**Audience**: Agents and scripts that read or write profile.json or config.json:
`aitools-profile.sh` / `aitools-profile.ps1`, `setup-user-config`, `aitools user init`,
`setup-user-*`, the tool exception helpers in `aitools-lib`, `build-deploy.sh`,
`ait-harvest.py`.

Private per-user companion repo for session archives and profile data.

## Location convention (the single definition)

`<reposPath>/aitools-<github-user>`

| Platform | reposPath default | Example |
|---|---|---|
| macOS | `~/repos` | `~/repos/aitools-nobul-jose` |
| Linux | `~/repos` | `~/repos/aitools-nobul-jose` |
| Windows | `%USERPROFILE%\repos` | `%USERPROFILE%\repos\aitools-nobul-jose` |

`reposPath` is the value the installer stored in config.json (Step 3), else the default.
The convention is implemented once per shell, in the native resolver:
`scripts/aitools-profile.sh` (macOS/Linux) and `scripts/aitools-profile.ps1` (Windows),
which implement the same commands, options and output (P-Q3; parity tested by
`tests/profile/test-profile.sh`). Consumers call it through the shared-lib wrappers
`resolve_user_repo_path` (`@scripts/aitools-lib.sh`) / `Resolve-UserRepoPath`
(`@scripts/aitools-lib.ps1`), or run `aitools-profile.sh user-repo-path` directly.
`build-deploy.sh` receives the result from the entry point as `AITOOLS_USER_REPO_PATH`
(forward-slash form); on macOS/Linux a standalone run asks `aitools-profile.sh` itself.

Path forms: config.json stores the native OS form; the exported `AITOOLS_USER_REPO_PATH`
uses forward slashes (`C:/...` on Windows), valid in Git Bash, PowerShell and node
(`@reference/logging.md` §2). `aitools-profile.ps1 --path-form mixed` prints that form.

JSON: both resolvers keep key order and write the node `JSON.stringify(v, null, 2)`
layout (LF, no BOM), so every writer of the shared `profile.json` produces the same
bytes. The bash side uses `scripts/aitools-json.pl` (core perl, no modules); the
PowerShell side uses `scripts/aitools-json.ps1`.

## Directory Structure

```
aitools-<username>/
├── profile.json          # Source of truth: identity, preferences, every machine
├── claude/
│   ├── CLAUDE.md          # Personal CLAUDE.md template ({{PLACEHOLDER}} tokens)
│   ├── hooks/             # User-level hook overrides (deployed to ~/.claude/hooks/)
│   ├── rules/             # User-level Claude Code rules (deployed to ~/.claude/rules/)
│   └── skills/            # User-level skill overrides (deployed to ~/.claude/skills/)
├── deploy/               # Generated by build-deploy.sh; shared by all this user's machines
├── sessions/             # Archived Claude Code transcripts, one directory per project
└── README.md
```

## Profile Schema (v2, revision 2.1)

`profile.json` holds every user-specific and user-customizable value, including every
machine the user has. It stays `"version": 2`: revision 2.1 only adds optional fields,
because aitools releases before this revision treat any version other than 2 as v1 and
offer a destructive migration. Removing a field that older releases read (for example a
profile's `company`) waits until every machine runs revision-2.1 code.

```json
{
  "version": 2,
  "meta": {
    "schemaRevision": "2.1",
    "intent": {
      "purpose": "Source of truth for one user's identity, tool preferences and machine inventory, shared across the user's machines through git",
      "scope": "identity, claude.settings, cursor.cli, overrides, and one profile per machine (machine.id, hostname, per-machine name/company overrides, toolExceptions). NOT per-machine bootstrap pointers (~/.aitools/config.json). NOT secrets or credentials. NOT session transcripts (sessions/)",
      "audience": "aitools-profile.sh/.ps1 (resolver; the only writer of machine entries and toolExceptions), setup-user-config, aitools user init, setup-user-settings, setup-user-claude, setup-user-cursor, build-deploy.sh, and the tool setup scripts through the tool exception helpers"
    }
  },
  "identity": {
    "github": "<github-username>",
    "email": "<primary-email>",
    "name": "<display-name>",
    "company": "<company>",
    "git": { "name": "<git-name>", "email": "<git-email>" }
  },
  "cursor": { "cli": { "vimMode": true, "model": "auto" } },
  "claude": { "settings": { "...": "verbatim settings.json keys except hooks" } },
  "profiles": {
    "<alias>": {
      "name": "<optional override of identity.name>",
      "company": "<optional override of identity.company>",
      "machine": {
        "id": "<the platform's stable machine id, raw>",
        "environment": "claude-code-web",
        "hostname": "<hostname when registered>",
        "hostnames": ["<optional extra names>"],
        "os": "<darwin|linux|win32>",
        "arch": "<arm64|x64>",
        "shell": "<shell>"
      },
      "toolExceptions": {
        "<tool-slug>": {
          "decision": "keep",
          "detected": {
            "platform": "<macos|linux|windows>",
            "method": "<registry method id, or unknown>",
            "path": "<PATH-resolved command path>",
            "version": "<bare version token at decision time>"
          },
          "decidedAt": "<UTC timestamp, Z suffix>",
          "decidedBy": "<setup script base name, e.g. setup-go>",
          "reason": "<optional free text, or null>"
        }
      }
    }
  },
  "overrides": { "<tool-name>": { "<flag-or-setting>": { "reason": "...", "added": "YYYY-MM-DD" } } }
}
```

- **`identity`** -- shared across all machines. `name` and `company` (2.1) are the
  defaults for every profile; a profile's own `name`/`company` overrides them.
- **`cursor`** -- Cursor CLI preferences. Read by `setup-user-cursor`.
- **`claude.settings`** -- the source of truth for `~/.claude/settings.json` (verbatim
  keys, EXCEPT `hooks`, which the manifest owns via `setup-user-hooks`). Synced by
  `setup-user-settings` via `sync_managed_json` (`@reference/managed-file-deployment.md`).
- **`overrides`** -- intentional deviations from upstream tool defaults. Informational
  only; mirrors the `overrides` section of the tool registry (`/tool-registry` skill).
- **`profiles`** -- keyed by alias. One per machine (or per environment, e.g. a Claude
  Code web profile with `machine.environment: "claude-code-web"`).
- **`machine.id`** (2.1) -- the platform's stable id, stored raw (P-Q2): macOS
  `IOPlatformUUID` (`ioreg -rd1 -c IOPlatformExpertDevice`; hardware-bound, survives an
  OS reinstall), Windows `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid` (read on the
  GitHub Windows runner; UNVERIFIED on the commander's workstation; changes on an OS
  reinstall, duplicated on clones that were not sysprepped), Linux `/etc/machine-id`
  then `/var/lib/dbus/machine-id` (duplicated on cloned images). Compared
  case-insensitively. Written only by registration (`aitools user init`, through
  `aitools-profile register`). Claude Code web profiles have no id (containers are
  ephemeral) and use `machine.environment`.
- **`machine.hostname`** -- informational and a legacy match key only.
- **`toolExceptions`** (2.1) -- per-machine `[k]eep` decisions of the tool support
  decision tree. The shape is fixed here; when an entry is written, read and
  matched is `@reference/tool-support-decision-tree.md` section 8. Entries are
  read and written only through `aitools-profile.sh` / `.ps1` (`exception-get` /
  `exception-set`, wrapped by `tool_exception_get` / `tool_exception_record` and
  `Get-ToolException` / `Set-ToolException`). `exception-set` writes in place
  (temp -> validate -> backup -> move), then commits only `profile.json` and pushes
  (N-Q2). `detected.platform` uses the `$AITOOLS_PLATFORM` values (`macos`, `linux`,
  `windows`), not `machine.os` (`darwin`, `linux`, `win32`). Distinct from top-level
  `overrides`: an exception keeps a whole install; an override changes a setting.
- **v1 migration** -- v1 (flat schema) is detected by the absence of `"version": 2`;
  `aitools` offers the migration to v2.

## Resolution

### Which dotprofile

`user-repo-path` (`resolve_user_repo_path` / `Resolve-UserRepoPath`), first match wins:

1. `AITOOLS_USER_REPO_PATH` (explicit; set by the entry point for build-deploy, and by tests). Missing directory = error.
2. `--user-repo-path` argument (user init's choice). Missing directory = error.
3. config.json `userRepoPath`, when the directory exists (otherwise a warning, and continue).
4. Convention `<reposPath>/aitools-<githubUser>` (githubUser from the caller or config.json).
5. The only `aitools-*` directory under reposPath that contains `profile.json` (migration aid for configs without `githubUser`; logged as a warning).
6. None -- shared-only mode (`shared/` content, no personal values). Not an error.

### Which machine profile

`resolve` (`resolve_machine_profile` / `Resolve-MachineProfile`), first decisive step
wins; every result carries `via`:

| # | Step | via | On a miss |
|---|---|---|---|
| 1 | Override alias (`AITOOLS_MACHINE_ALIAS`, or `--alias` / user init's `--machine-alias`) | `override` | unknown alias = error |
| 2 | Environment `claude-code-web`: the one profile with that `machine.environment` | `environment` | two such profiles = error |
| 3 | `machine.id` equals this machine's id | `id` | id on two profiles = error |
| 4 | config.json `machineAlias` | `alias` | unknown alias = warning, continue |
| 5 | Hostname: text before the first dot, trimmed, ASCII lower-cased. One source per platform (P-Q5): macOS `scutil --get LocalHostName` (the kernel hostname comes from DNS/DHCP and is never used), Windows `COMPUTERNAME`, Linux `uname -n` | `hostname` (warning: register) | two matches = error |
| 6 | None | `none` | **error**; no other profile's values are used |

Warnings: a profile selected by steps 1 or 4 that has no `machine.id` asks for
registration; a profile whose `machine.id` belongs to another machine is reported; a
config alias that disagrees with the id match is reported (the id wins).

On `none`, consumers still receive identity-level values (identity name, company, git);
machine-specific tokens stay unresolved and the run reports `write_summary ERROR
"machine profile" "no machine match"` plus `ACTION Run: aitools user init`.

Every consumer logs one line, e.g. `machine profile: alias=nobul-mac via=id company=nobul-tech hosts=nobul-mac id=<IOPlatformUUID>`.

Exit codes of `aitools-profile`: 0 resolved, 1 nothing found (expected states, e.g.
before `aitools user init`), 2 error, 3 refused (`exception-set` only). A setup script
never passes 2 through as its own exit code (exit 2 means a user abort, D-TS13).

### Registration (`aitools user init`)

Path 1 (repo present), Path 2 (clone) and Path 3 (new repo) all resolve first. When the
result is `none` or `hostname`, user init asks (numbered aliases, `[n]ew`, `[s]kip`;
identical in bash and PowerShell), or takes `--alias <A>` without a terminal (P-Q12);
then `aitools-profile register` writes `machine.id`, `hostname`, `os`, `arch`, `shell`
into that profile (temp file -> validation -> backup -> move), and user init commits
and pushes the dotprofile (N-Q2). Without a terminal and without `--alias` it reports
ERROR + ACTION and does not guess.

## Config Schema (v3)

`~/.aitools/config.json` is per machine, untracked, and **derived**: its only writer is
`setup-user-config.sh` / `setup-user-config.ps1`. Do not edit it by hand.

```json
{
  "version": 3,
  "reposPath": "/Users/pepe/repos",
  "repoPath": "/Users/pepe/repos/aitools",
  "googleDrives": [ { "path": "...", "account": "user@example.com", "label": "" } ],
  "githubUser": "nobul-jose",
  "userRepoPath": "/Users/pepe/repos/aitools-nobul-jose",
  "machineAlias": "nobul-mac",
  "meta": {
    "intent": { "purpose": "...", "scope": "...", "audience": "..." },
    "writer": "setup-user-config",
    "derivedFrom": "profile.json"
  }
}
```

| Key | Class | Source | Passed by |
|---|---|---|---|
| `version` | schema | writer | -- |
| `reposPath`, `repoPath` | bootstrap pointer | installer Step 3 / script location | `aitools install` |
| `googleDrives` | detected | installer Step 4 (kept when nothing is detected) | `aitools install` |
| `githubUser` | derived | `--github-user`, else `profile.json identity.github` | user init / every sync |
| `userRepoPath` | derived | "Which dotprofile" (not saved when it came from `AITOOLS_USER_REPO_PATH`) | every run |
| `machineAlias` | derived | "Which machine profile" (cached result; not saved from `AITOOLS_MACHINE_ALIAS`) | every run |
| `meta` | self-description | writer | -- |

Callers: installer Step 5 (bootstrap values), `aitools user init` (GitHub user,
dotprofile path, chosen alias), and the first entry of every `aitools` deploy list
(re-derivation). Write path: read-then-merge (every other key kept in place) -> temp ->
validate -> `backup_file` -> move; outcomes created / updated / verified (no write) /
recovered (invalid JSON rebuilt from salvaged keys, WARN). The writer needs no node
(P-Q3). Resolver warnings about the cached config.json are corrected by the write and
logged as info; warnings that need the user add an ACTION.

v1 and v2 files are read as-is (all their keys keep their meaning); the first writer run
upgrades them to v3 by adding `githubUser` and `meta` and re-deriving the rest.

## Session Naming

`<YYYY-MM-DD>_<session-id-prefix-8>.jsonl`

- Date: session creation date (from transcript file birth time, fallback to today)
- Session ID prefix: first 8 characters of the Claude Code session ID

## Project Derivation

Sessions are filed under a project name derived from the working directory:

1. If cwd is inside a git repo: `basename $(git rev-parse --show-toplevel)`
2. Otherwise: sanitized basename of cwd (lowercased, non-alphanumeric replaced with `-`)

**Known limitation:** cwd may not match the project being worked on (e.g., running Claude Code from `~/scratch` while working on `mbx-ext`). Use `aitools sessions move` to refile.

## Archiving Mechanism

Claude Code `SessionEnd` and `SessionStart` hooks carry session transcripts and
scratch artifacts forward into the user repo. The hooks are thin shims; all logic
lives in `scripts/ait-harvest.py` (Python stdlib, no deps), deployed to
`~/.claude/hooks/ait-harvest.py`.

- **`session-archive.sh`** (SessionEnd) → `ait-harvest.py archive`: copies the
  session transcript **and its subagent transcripts** to
  `sessions/<project>/<date>_<prefix>.jsonl`, then `git add` (specific file) +
  commit + push. Best-effort: `git pull --rebase` first for concurrent sessions,
  warns on failure, never blocks SessionEnd.
- **`session-catchup.sh`** (SessionStart) → `ait-harvest.py`: recovers
  transcripts (incl. subagents) and `.scratch/` artifacts that an abrupt,
  offline, or slept SessionEnd missed. Concurrency-safe (single-flight lock,
  mtime liveness, skip-own-session via stdin sid).
- **`harvest-session.sh`** (SessionEnd): harvests reusable `.scratch/` artifacts
  into `harvesting/`.
- Project name is derived from the session's working directory; `userRepoPath`
  is read from `~/.aitools/config.json`, which is derived (see "Config Schema"),
  so the archive follows the same dotprofile as every other consumer. Silently
  skips if config is missing or the user repo doesn't exist.
- The helper logs to `~/.aitools/logs/ait-harvest.log` (size-based rotation —
  see `@reference/logging.md`).

The `SessionEnd` hook API contract (session_id, cwd, transcript_path on stdin) is
a CC version dependency — see `@reference/tool-ops-claude-code.md`.

## Template Resolution (CLAUDE.md)

Setup scripts read CLAUDE.md templates in priority order -- on the dev path
(`scripts/setup-user-claude.*`) and the MDM path (`<dotprofile>/deploy/setup-user-claude.*`) alike:

1. `<userRepoPath>/claude/CLAUDE.md` -- personal template (syncs across machines via git)
2. `aitools/shared/claude-shared.md` -- fallback for users without a companion repo

Tokens, resolved **at run time on the target machine** by the resolver:
`{{PROFILE_NAME}}`, `{{PROFILE_COMPANY}}`, `{{IDENTITY_GIT_NAME}}`, `{{IDENTITY_GIT_EMAIL}}`,
`{{USER_REPO_PATH}}` (display form: `~/...` on macOS/Linux, `%USERPROFILE%\...` on Windows).
An empty value leaves its token in place. The generated deploy scripts embed the resolver
and a snapshot of `profile.json` (`aitools-profile snapshot`, without `claude.settings`);
they use the live `profile.json` when the dotprofile exists on the machine and the
snapshot otherwise, so one committed deploy/ is correct for every machine.

The deployed `~/.claude/CLAUDE.md` ends with a `## Machine-Specific` footer: OS, arch,
hostname, the resolved profile alias, and shell.

## User Rules Deployment

Setup scripts deploy user-level Claude Code rules from `<userRepoPath>/claude/rules/` to `~/.claude/rules/`.

**Semantics**: additive deploy — managed files are added/updated, unmanaged files in the target are preserved.

- **Source**: `<userRepoPath>/claude/rules/*.md`
- **Target**: `~/.claude/rules/*.md`
- **Backup**: full directory copy (`rules.bak.<TIMESTAMP>/`), max 5, auto-prune
- **Diff logging**: unified diff of changes logged to deploy log; console shows summary
- **Managed vs preserved**: files matching a source file are managed; all other files in the target are preserved and logged

**Scope guidance**: user-level rules should be universal conventions that apply across all projects. Project-specific rules belong in `.claude/rules/` within the project repo.

**Build-time embedding**: `build-deploy.sh` reads user rules at build time and embeds them in deploy scripts via heredocs. If no rules exist at build time, deploy scripts skip rules deployment.

## Relationship to aitools

The user repo is a companion to `aitools`, not a submodule. It contains personal data (session transcripts, profile) that shouldn't be in the shared repo. The `aitools` repo provides the hook script and CLI commands that operate on the user repo.

## What Stays in aitools/shared/

The `shared/` directory contains framework content shared across all users.
User repos hold personal data only. This boundary is intentional:

| aitools/shared/ | Purpose | Why not user repo |
|--------------------|---------|-------------------|
| `claude-shared.md` | Fallback CLAUDE.md template | Bootstrap for new users; user repo takes priority |
| `hooks/session-archive.sh` | SessionEnd hook source (deployed to `~/.claude/hooks/`) | Framework code operating on user data |
| `shell/aliases.sh` + `.ps1` | Cross-platform shell aliases | Shared tooling, not personal |
| `skills/` | Chrome DevTools / a11y skills | Vendored from upstream |
| `mcp/` | MCP server config docs | Reference docs |
| `cursor-rules/` | Template Cursor rules | Project-level, not personal |

## CLI Commands

| Command | Description |
|---------|-------------|
| `aitools user init` | Set up or clone the dotprofile, register this machine's profile, write config.json via setup-user-config |
| `aitools sessions list [project]` | List archived sessions |
| `aitools sessions archive <session-id>` | Manually archive a session |
| `aitools sessions move <file> <project>` | Refile a session under a different project |

## Known Limitations

### `sessions move` is archive-only

`aitools sessions move` refiles the archived transcript in the user repo's `sessions/`
directory. It does **not** affect Claude Code's internal session resolution, which is
tied to the sanitized CWD path in `~/.claude/projects/`. A session started from
`/Users/pepe/repos/ai-tooling` will always resolve to the `-Users-pepe-repos-ai-tooling/`
directory -- `sessions move` only changes where the archive copy lives.

### Resolver parity limits

The PowerShell JSON reader treats property names case-insensitively (keys differing only
in case, or an empty key, are rejected) and re-formats non-integer number literals;
profile.json holds neither. Details: the headers of `aitools-profile.sh` / `.ps1`.
