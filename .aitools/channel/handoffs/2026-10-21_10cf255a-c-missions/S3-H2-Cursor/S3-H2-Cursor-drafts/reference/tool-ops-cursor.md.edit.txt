--- New ---
`setup-user-cursor` step 4 fans the user-level rules of `~/.aitools/rules`
out here (commander decision 2026-10-22). It reads the rules manifest
deploy-harness writes, `~/.aitools/rules/.aitools-rules-manifest`, and takes
only names whose source is `shared` or `dotprofile`. It converts each
Claude Code `<name>.md` to `<name>.mdc`:

- A rule without frontmatter gets `alwaysApply: true`.
- A Claude Code `paths:` key (any form) becomes an anchored `globs:` block
  list (`**/<pattern>`) with `alwaysApply: false`.
- The line after the frontmatter is the aitools-fanout marker
  (`<!-- aitools-fanout: generated by setup-user-cursor from ~/.aitools/rules/<name>; ... -->`).
- A converted file that Cursor would misparse (a `---` inside a frontmatter
  value) is reported as a warning.

For a manifest name whose source is `aitools` (project rules) or `retired`,
the step backs up and removes `~/.cursor/rules/<stem>.mdc`, but only when the
fan-out created it: the marker, or (a file from before the marker) the same
content as the conversion of the harness copy. Any other file of that name is
kept. With no manifest, or one whose first line is not
`# aitools rules manifest v1`, nothing is fanned out or removed (WARN row and
ACTION: run aitools).
