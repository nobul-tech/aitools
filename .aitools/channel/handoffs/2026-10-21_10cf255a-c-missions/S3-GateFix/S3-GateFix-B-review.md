# S3-GateFix-B review: tool support decision tree rev 5 (cross-platform and bootstrap lens)

**Intent**: **Purpose**: Give mission S3-GateFix a rated, evidenced list of defects in the tool support decision tree rev 5 that appear only on a specific platform, shell, or bootstrap state, so blockers and majors are fixed before the commander's gate. **Scope**: The rev 5 draft only, through a cross-platform/bootstrap lens: APFS case sensitivity, PowerShell and Windows paths, Git Bash vs WSL bash, `/bin/bash` 3.2 on macOS, first run without node, exit 2 and the abort marker (section 7.5, including the runner coverage for `deploy_configs` / `Deploy-Configs`), and the RP guard. NOT rule-correctness findings that hold on every platform (short "outside lens" list only). NOT editing the tree or any other draft. NOT filing incidents. NOT shipping a PR. **Audience**: S3-GateFix (merges blockers/majors into rev 5), the session commander, the commander at the gate.

Reviewer: S3-GateFix-B (independent; S3-Gate-B-review.md not read until the findings below were written). Date 2026-10-21. Machine: Darwin 27.0.0 arm64, `/bin/bash` 3.2.57, pwsh at /opt/homebrew/bin/pwsh. Every Windows claim is UNVERIFIED (read, not run).

## Summary (5 lines)

1. No blockers; 5 majors, 10 minors, 1 info. The D-TS13 marker mechanism itself works on macOS (bash 3.2 and pwsh, in-process and `-File`): probes P1, P3, P4.
2. Section 7.5 says "four runners, all four": wrong. `aitools user init` launches `setup-user-hooks` in both entry points and ignores its exit code, and `bootstrap.sh` / `bootstrap.ps1` launch the installer and then `aitools` with no abort handling (GB-01, GB-03).
3. bash-only defect: helpers that *print* their result (`tool_update`, `tool_install`, `tool_detect_method`, `tool_exception_get`, `tool_method_menu`) run inside `$(...)`, so their `log_warn` / `log_error` counts and the `TOOL_UPDATE_STATE` global are lost (probe P1-7). The T4 "promoted to WARN" rule and the exit footer then fail on bash only. PowerShell keeps them (P3) (GB-02).
4. Windows: PS1 setup scripts launched from Git Bash `aitools` inherit Git's `usr/bin` ahead of the managed directories, and `Refresh-Path` only adds entries. So T2/T7 can report SHADOWED (ERROR) under one entry point and OK under the other, for example perl (GB-04, UNVERIFIED).
5. APFS: perl `Cwd::abs_path` keeps the caller's case on case-insensitive APFS, while `/bin/realpath` returns the on-disk case (P2, P5). So the section 5 "inside" checks and the RP "differs" check depend on how PATH is spelled, and BSD `tr` does not lowercase non-ASCII (P1-8) (GB-05, GB-06).
