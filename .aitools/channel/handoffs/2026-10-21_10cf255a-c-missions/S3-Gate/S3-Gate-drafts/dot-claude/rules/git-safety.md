### deploy/ is ephemeral

`deploy/` is 100% generated by `build-deploy.sh`. The `aitools` entry points
reset it to HEAD before every pull (`git checkout HEAD -- deploy/`). Uncommitted
changes in `deploy/` will not survive an `aitools` run — this is by design.

After running `build-deploy.sh`, `deploy/` will have uncommitted diffs (newly
generated content). These are expected. They are committed as part of the normal
release flow and cleared by the pre-pull reset on the next run.

### generated/ is generated and tracked

`generated/` holds committed files derived from governed data, starting with
`generated/tool-specs/<slug>.sh` and `.ps1` (written by `scripts/gen-tool-specs.py`
from the tool registry; `@reference/tool-support-decision-tree.md` "Tool spec
input"). Rules:

- Never hand-edit a file under `generated/`. Change the source (through its
  governing skill) and regenerate.
- Regenerate only when the source changes. Commit the regenerated files in the
  same commit as the source change. Pre-commit check "Tool support conformance"
  (check 7) fails when the committed files are stale.
- `generated/` is NOT part of the pre-pull reset. Unlike `deploy/`, nothing
  rewrites it during a normal run, so a diff there is a real, uncommitted change,
  not build noise.
- `build-deploy.sh`, the installers and setup scripts read `generated/` and never
  write it.

### scripts/ is source — never bulk-reset

`scripts/` contains source files (aitools-lib, setup scripts, entry points).
The pre-pull reset must NEVER include `scripts/` or any other source directory.

If a build step creates noise diffs in source directories (mode changes, line
endings), fix the build step — do not add the source directory to the pre-pull
checkout.

### Pre-pull reset scope rule

When modifying pre-pull reset logic in `scripts/aitools` or `scripts/aitools.ps1`:
- Only include directories that are fully generated AND rewritten on every run
  (currently: `deploy/`; `generated/` is generated but not rewritten, so it is
  excluded)
- Never include directories containing source files
- If adding a new directory, document WHY in the code comment and in this rule
