## 8. Spec ambiguities (INCIDENT markers, not filed)

- **I-1** `INCIDENT:` reference/logging.md defines no deploy.jsonl -- not its writers, schema, rotation or which runs must produce it -- yet S3-M3Lead decision 3 requires "deploy.jsonl coverage". Today only the installers write it (install.sh:124, install.ps1:51); `aitools` sync, user init and every setup script write none; the lib's `jsonl_record` / `Write-JsonlRecord` have no caller. A fix mission cannot tell what "coverage" must reach. Related: A-1, A-12, A-16.
- **I-2** `INCIDENT:` script-standards-detail "Severity decision guide" / "ACTION items" require every ACTION to pair with a same-text `log_warn`, but `write_summary` auto-promotes OK to WARN once a warning is counted (not stated in the guide) and D-TS12 wants a successful step to stay OK, so the lib and the config writer pair ACTIONs with `log_error` or different text instead. Related: A-5, A-10. (Same root as the S3-M3-ConfigKey-Review INCIDENT on auto-promote.)
- **I-3** `INCIDENT:` script-standards has no category for a library-style tool (aitools-profile.sh/.ps1: data on stdout, diagnostics returned as `warn`/`error` lines, no exit footer, no summary rows, raw stderr). Its contract lives only in its own header. Related: A-6.
- **I-4** `INCIDENT:` no spec says whether a consumer re-counts an error the lib wrapper already logged (lib `log_error` + ERROR row) when the consumer's own step also fails; the "S3-M3Lead decision" exists only in code comments (setup-user-settings.sh:73) and the consumers disagree. Related: A-23.

## 9. Confirmations

**(a) No alias-keyed profile lookup remains -- confirmed, with the designed legacy reads.** Profiles are keyed by raw machine id: `register` writes only `profiles.<lc(machine id)>` (profile.sh:1258-1270 / ps1:1097-1111) or `environment:claude-code-web`. build-deploy.sh and its templates contain no `profiles[` / `machineAlias` lookup (grep over scripts/: hits only in the resolver, the config writer, the lib comments, user init comments and the v1 migration's `v2.profiles["machine"+n]` writer at aitools:771-772 / aitools.ps1:1369-1370); the generated setup-user-claude reads only lib results (build-deploy.sh:656-686; setup-user-claude.sh:65-70). The live dotprofile deploy/ holds `machineAlias` only in lib comments (aitools-nobul-jose/deploy/setup-user-claude.ps1:126). profile-check.js checks only `machineId` (profile-check.js:115-135). What remains, by design: (1) the explicit override `--alias` / `AITOOLS_MACHINE_ALIAS` matches a key, else an `alias` field (profile.sh:642-663 / ps1:520-532); (2) step 4L reads config.json `machineAlias` only for a legacy alias-keyed profile and only when config.json has no `machineId` (profile.sh:722-738 / ps1:572-585); (3) legacy 2.1 profiles are read (`kind=legacy`, profile.sh:525-527). So `machineAlias` is display-only for id-keyed profiles and the legacy cache for 2.1 profiles, as the writer header says (setup-user-config.sh:22-24); it is written for one release (setup-user-config.sh:282 / ps1:284).

**(b) Decision 2 cached-alias behaviour unchanged -- confirmed.** One named switch per entry point: `AITOOLS_REGISTER_CACHED_ALIAS_SILENTLY=0` (aitools:137-143) and `$script:RegisterCachedAliasSilently = $false` (aitools.ps1:755-761). via=alias with the switch at 0 goes to the menu with the profile suggested (aitools:695-701, 705-706 / ps1:1296-1309); without a terminal `ui_choose` / `Read-UiChoose` gives `log_error` + `ERROR|machine profile|not registered (no terminal)` + ACTION (aitools:402-406 / ps1:1002-1006). Nothing removed.

**(c) Item 5 approved choices present -- confirmed.** Duplicate alias only after an interactive confirm: the resolver refuses (exit 4) unless `--allow-duplicate-alias` or the alias is the entry's own (profile.sh:1339-1352 / ps1:1168-1180); user init passes the flag only after `[y/N]` on a terminal and gives ERROR without one (aitools:498-509 / ps1:1091-1103); every resolve warns "alias ... is used by N machines" (profile.sh:621-627 / ps1:504-506), which setup-user-config logs as a real `log_warn` (setup-user-config.sh:182-183 / ps1:185-186). exception-set on a legacy entry matched by id: allowed (owner `this`, via id; profile.sh:1051-1074 / ps1:890-913) with the resolver's "is keyed by alias -- run: aitools-profile migrate" warning (profile.sh:693-694 / ps1:549-550); the lib logs that warning at detail (lib.sh:432 / ps1:363), and setup-user-config turns it into the one ACTION "Run: aitools user init (re-keys machine profiles by machine id)" (setup-user-config.sh:180-181, 375 / ps1:182-184, 372). machineAlias kept: (a).

**(d) Item 6, Path 3 creates the private GitHub repo without a terminal -- confirmed.** `ans` defaults to "y" and is asked only when `ui_can_ask`; without a terminal `gh repo create --private --source --push` runs with `GIT_TERMINAL_PROMPT=0` and ssh BatchMode (aitools:847-865 / aitools.ps1:1452-1475).
