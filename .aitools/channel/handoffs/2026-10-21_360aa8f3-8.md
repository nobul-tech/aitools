## H. New concepts

- **Folder = level** (S2-Layout): `shared/**` deploys to user level, `.claude/**` / `.cursor/**` are project-only, and everything else is source. **N2 one-name rule:** a skill or rule name exists in exactly one of `shared/`, `.claude/`, or dotprofile `claude/`.
- **`aitools-registry.py` resolver:** user-level skills read registries through it. Order: live clone (read-write only inside a worktree of the clone), then the `~/.aitools/registries/` read-only snapshot, then "unavailable".
- **`aitools-profile.js`:** the single resolver and writer for machine identity, config derivation and tool exceptions. Answers carry `via` = override | environment | id | alias | hostname | none.
- **Proposed glossary terms** (S4 merged draft): tool adoption, tool exception, update channel, machine profile, machine alias, machine id (renamed from "machine identity"), aitools config (renamed from "derived config"); `managed tool` modified.
- **Decision-tree leaves:** NA, EVALUATING, NO-METHOD, PREREQ, INSTALL-FAIL, EXCEPTION, HOLD, KEEP, ABORT, REPLACE-FAIL, REPLACE-BLOCKED, OK, SHADOWED, NOT-ON-PATH, VERSION-UNKNOWN, BELOW-MIN. **RP guard:** replace never removes the only copy that resolves. **Exit 2 = user abort** from a setup script; a script never passes a helper's rc 2 through.
- **Mission labels:** M2 = tool support, M3 = profile/config, M4 = node, M5 = issue #32, M6 = hook lifecycle. X-B1..X-B4 are the cross-mission batches.

## I. Delegation and operational notes (Claude Code)

- **Nested `.claude/` hazard.** Claude Code loads nested `<dir>/.claude/skills` once it works on files in that directory. That is why the draft folders in `MISSIONS/` are renamed `dot-claude/`. Never copy drafts into a tracked `.claude/` subfolder, and read draft skills with Read only.
- **`/delegate` is not deployed.** It is absent from `~/.claude/skills`, and redeploying waits on G1. Read `shared/skills/delegate/SKILL.md` directly before delegating. Also read `~/repos/aitools-nobul-jose/claude/rules/delegation.md` explicitly: it is not in `~/.claude/rules`, so the D-DEL rules are not in context otherwise.
- **Subagent context gap:** delegates do not inherit project rules. Inject the error-handling block from `reference/plan-execution-detail.md`, the D-DEL1 name prefix, D-DEL4 shipping and its limits, and the WRITE_BLOCKED instruction.
- **WRITE_BLOCKED:** background or isolated delegates can be denied Write. Every brief must say: record `WRITE_BLOCKED: <what> -- <text>`, return the content, and do not retry another way. The delegating agent then writes it.
- **Worktree-isolated delegates cannot write outside their worktree.** That includes the main checkout's `.scratch/` (#83). Name output paths inside the worktree, or do not isolate.
- **Session restarts reset the scratchpad and kill running reviewers.** That is how S4-Review A/B were lost. Preserve outputs to tracked paths early.
- **standing-order-guard** blocks `&&`, `||`, `;`, `$()`, backticks, multi-line commands, and `cat/head/tail/sed/awk` outside a pipeline. That includes read-only `sed -n` (#82). Use Read, scratch scripts, separate Bash calls, and `git commit -F`. Use the Grep tool when present. It is sometimes absent, and bash `grep` ran unblocked on 2026-10-21.
- **build-deploy.sh:** isolated `HOME` only (F2).
- **Firecrawl credits are exhausted.** Use chrome-devtools for docs that feed protected files, and WebFetch for low-stakes reads.
- **pwsh is installed** (`/opt/homebrew/bin/pwsh`) and can parse-check PS1 locally. The M3 PS1 drafts parse cleanly and their resolver wrappers ran under pwsh on macOS (S5-Profile report, tests table). No PS1 path has been executed on Windows.
- **`delegation-duty-guard.sh`** is in observe mode: it prints missing duty elements to stderr and does not block.
