## H. New concepts

- **Record**: one line of the run summary file (`AITOOLS_SUMMARY_FILE`):
  `OK|tool|status`, `DETAIL|tool|detail`, `WARN|name|text`,
  `ERROR|name|what|reason`, `ACTION||instruction` (logging.md 8.4). Legacy
  3-field `WARN|tool|text` / `ERROR|tool|text` are read until I5.
- **Recorded at the source**: each warning and error is recorded once by the
  script that logs it; `write_summary` never changes a category (no more
  "promotion" of OK to WARN).
- **Relay**: a parent running a child through `run_child_relayed` /
  `Invoke-ChildRelayed` / `Invoke-NativeRelayed`; the child's warnings are not
  counted in the parent; a failed child is one ERROR with a reason, only if it
  recorded none itself; only the outermost relay mirrors to deploy.jsonl
  (`AITLIB_RELAYED`). **R5**: the caller writes no second row for a relayed
  child.
- **Demotion**: a warning that reports a step the user explicitly asked for
  and that completed as asked becomes `log` (info) (logging.md 8.3 "What is a
  warning").
- **I1b kinds**: 1 expected change (update), 2 real regression (report, keep
  the correct assertion), 3 unstable text (normalize or per-platform golden).
- **Cross-group suite**: a suite fed by more than one I3 group; regenerated
  only once, in I5.
- **Migration switch** `AITLIB_RECORD_LOG_CALLS` and **report-then-fail**
  `STRICT_SUMMARY`: both flipped in I5.
