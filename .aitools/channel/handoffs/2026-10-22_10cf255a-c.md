### D.3 Approved decisions (binding; essentials inline)

All 95 items are in `plans/tool-support-and-machine-profile.md`. The ones that change behaviour:

- **D-TS13 reversed:** a bare exit 2 from a setup script = user abort. There is no abort-marker file. (Installers still continue after exit 2: incident #87, open.)
- **Managed-file model:** SOURCE (the repo) is the source of truth; no ancestor and no deploy state. One review menu: `[o]verwrite` / `[a]ccept & adopt` / `[m]erge & adopt` (AI, text only) / `[s]kip` / `[x]abort` (exit 2). Adopt and merge copy to the repo immediately. JSON is reviewed field by field, and SOURCE owns every field. Back up, validate, restore on failure, write an ERROR row, continue.
- **Registries stay in `registries/`.** deploy-harness copies them to `~/.aitools/registries/` (`%USERPROFILE%\.aitools\registries\` on Windows). `tool-versions.json` is deleted. `tool-registry.md` is deprecated (use the `/tool-registry` skill).
- **SD-8 extended:** 7 skills at user level (tool-ops, tool-eval, tool-registry, harvest, incident, glossary, frameworks). `audit` and `governed-data` stay project-level. `git mv` only, never two copies (S2L-QA). **Not on main: D.2.**
- **Machine identity:** raw machine ids (P-Q2); native resolver `scripts/aitools-profile.sh/.ps1` (P-Q3); on macOS one scutil command, `LocalHostName` (P-Q5); profiles keyed `profiles.<machineId>` with the name as a field (M3Lead decision 5); no first-profile fallback (SD-7: an unresolved profile is an ERROR).

- **Dotprofile writes auto-commit and push** (N-Q2). Not yet true for managed-file adopt into the dotprofile (mission M3-FINISH is fixing it).
- **config.json** is derived from profile.json and has one writer, `setup-user-config.sh/.ps1`. The writer is silent; `aitools user init` prompts (P-Q4). `--machine-id <key>` / `-MachineId <key>` is the interface (M3Lead plan 3b).

## H. New concepts

- **deploy-harness / `~/.aitools`:** the harness copy on each machine (`reference`, `registries`, `hooks`, `rules`, `skills`, `bin`). Tools read from it first and the repo second (#85). Summary row name: `harness files`. On a name conflict the first source wins, and every skipped duplicate is `log_error` + an ERROR row.
- **Fan-out:** a consumer copies `~/.aitools/rules/*.md` (skipping `*.bak.*`) into its tool's rule directory. On main only setup-user-cursor does it (`.mdc` files, #87). setup-user-claude's fan-out is G12 (in flight, needs HARNESS Q1).
- **Superseded names you will meet in the plan and the prior handoff:** `aitools-profile.js` is now `scripts/aitools-profile.sh/.ps1` (P-Q3); `profiles.<alias>` is now `profiles.<machineId>` (M3Lead decision 5), including P-Q6's googleDrives; the `aitools-registry.py` resolver and `shared/registries/` were dropped (SD-8-reg); hashed `machine.id` is now raw ids (P-Q2).
- **Machine id key:** `profiles.<machineId>`; the human name is a field; config.json carries `machineId` (and `machineAlias` for display only).
- **`AITLIB_*` / `$script:AitLib*`:** the lib result-variable contract; consumers copy the result into a local variable right after the call.
- **Mission labels:** M2 tool support, M3 machine profile, HARNESS (deploy-harness), LAYOUT (skill levels), SOURCE-TRUTH (managed files), M3-FINISH and HARNESS-2 (the two missions running at write time).

## I. Delegation and operational learning (Claude Code)

- **Launch commanders that must delegate with the Agent tool, not with workflows.** Delegates launched through the Agent tool here have no Workflow tool, and level-3 delegates have no Agent tool (packet section 3).
- **Orchestrator missions that delegate small batches avoid context exhaustion.** Mission PROFILE-TOOLS ran out of context at batch B5 (reported by the Session Commander; its cause beyond context size is unknown). The M3-LEAD and HARNESS orchestrators, which gave each batch to a fresh delegate, shipped all their batches.
- **Usage limits stop missions mid-work: commit and push after every batch.**
- **Never switch the main checkout's branch** (worktrees only). **Never remove another agent's worktree** (it deletes ignored files; the S3-Hooks harness scripts were lost that way).
- **Scratch dir names are 10 characters or fewer** (`<worktree>/.scratch/session-<NAME>`); longer names make the catch-up harvester hit a live session (S3-SR-8).
- **Reviewers post verdicts as PR comments** (`gh pr review --comment`). GitHub refuses `--request-changes` on a PR opened by the same account, so a "changes needed" verdict must say so in the comment body.
- **Verify code, not issue or incident state**, before working on an "open" item. This session's ledger lags the code (G5).
- **Check a PR's base before merging a stack.** Four PRs were merged before their reviews were addressed (#56, #58, #76/#77, #79), and #74/#75 merged into stale bases. Retarget stacked PRs to `main` once the PR below merges.
- **Contract drift between missions:** pin the interface (flag names, markers, helper names) in the plan file and make each consumer check it against the code; launch prompts named a non-existent flag and non-existent build markers this session.
- **WRITE_BLOCKED:** any denied write or tool call is recorded as `WRITE_BLOCKED: <what> -- <exact text>`, not retried another way; the content goes in the response.
- **standing-order-guard:** no `&&`, `||`, `;`, `$(...)`, backticks or multi-line commands; `cat/head/tail/sed/awk` outside a pipeline are blocked (read-only `sed -n 'Np' file` is allowed). Use Read, separate Bash calls, scratch scripts, `git -C`, and `git commit -F`. To wait for a condition, use the Monitor tool, or run a scratch script with an `until` loop (a foreground `sleep` and an inline `until ...;` are blocked).
- **Delegates sometimes lack Grep and Glob.** Tell them to use Bash `grep`/`find` in pipelines or scratch scripts when those tools are absent.
- **Skills after the re-land.** Once #74 merges, the 7 governance skills are missing at both levels until the commander runs `aitools`. Read `shared/skills/<name>/SKILL.md` and follow it by hand (packet section 2).
- **Relative paths escape isolation.** A relative path in `config.json` writes into the agent's cwd under an isolated HOME (S3-M3-UserInit-report.md:98), and a check script started with a relative path ran against the main checkout (S3-SpecRewrite-report.md:34). Run checks from the worktree, by absolute path.
- **`.ps1` files check out with CRLF:** line-anchored grep/perl patterns in tests silently miss them. PowerShell variable names ignore case (`$e` vs `$E` collide).
- **Subagent context gap:** delegates do not inherit project rules; pass the packet path, the error-handling block from `reference/plan-execution-detail.md`, D-DEL1 prefixes and D-DEL4 limits.
