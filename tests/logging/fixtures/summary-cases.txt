# summary-cases.txt -- the shared fixture of tests L1-L32 (plan
# summary-warn-reporting section 13): for each case, its input and its expected
# run summary records, counts, deploy.log lines and panel lines.
#
# v1.0 (2026-11-15). Read by tests/logging/test-logging.sh (macOS, Linux) and
# tests/logging/test-logging.ps1 (Windows). One file, so the bash and PowerShell
# expectations cannot drift apart. Every expected value is derived from
# reference/logging.md section 8 (8.2 helpers, 8.3 rules, 8.4 the run summary
# file, 8.5 the panel). Where plan section 13 and section 8 disagree, section 8
# wins; the case says so in a "note" line.
#
# ---------------------------------------------------------------------------
# FILE
# ---------------------------------------------------------------------------
# UTF-8 without a BOM, LF line ends (.gitattributes "* text=auto eol=lf"
# keeps LF on every checkout). No raw CR, ESC or TAB byte appears in this file:
# they are written as escapes (below), so git's line-end handling cannot
# change a case.
#
# A line whose first character is "#" is a comment. An empty line is ignored.
# Every other line is:   [@sh |@ps1 ]KEYWORD[ REST]
#   - "@sh " / "@ps1 " at the start: the line applies to that harness only.
#   - KEYWORD runs to the first space. REST is everything after that one
#     space, kept exactly (leading spaces included).
#   - A line never ends with a space; a value that must end with one writes
#     the last space as \s.
#
# Escapes, decoded in every REST value after it is split (below):
#   \\  backslash        \p  |  (needed only inside "call" arguments)
#   \n  LF               \r  CR           \t  TAB        \e  ESC (0x1B)
#   \s  space            \u{HEX}  the code point HEX
# Any other backslash sequence is a fixture error: the harness fails the case.
#
# Splitting: "call", "relay", "relay-native" and "file" split REST on "|"
# first, then decode each part. Keep trailing empty parts: "write_error|t|w|"
# has 4 parts, the last one empty (Perl: split /\|/, $rest, -1; PowerShell:
# $rest -split '\|' keeps them). Every other keyword decodes REST whole, so
# "record" and "expect record" lines keep their literal "|" separators.
#
# ---------------------------------------------------------------------------
# CASES
# ---------------------------------------------------------------------------
# case ID          starts a case (ends at the next "case" line or end of file)
# plan ID          the plan section 13 case it covers (L1 ... L32)
# title TEXT       what it tests
# spec TEXT        the logging.md sections it is derived from
# lang both|sh|ps1 which harness runs it (default both)
# note TEXT        a remark: a difference from plan section 13, an open point
# needs pty        the case needs a terminal: a harness without one reports
#                  the case as SKIP with the reason, never as PASS
# migration-only   valid only while the recording switch and the legacy
#                  write_summary WARN / ERROR exist (until plan step I5);
#                  I5 deletes the case
# external PATH    the case is covered by another suite (PATH and its .ps1
#                  twin); the harness runs nothing for it
#
# Every case runs in a fresh process, in its own temp directory {CASEDIR},
# with stdin from the null device, AITOOLS_LOG_DIR={CASEDIR}/logs, and the
# library loaded with script name "test-logging" (logging_init test-logging /
# Initialize-Logging "test-logging"). "the script" below is that process.
#
# Setup lines (before the steps):
# switch on|off    the migration switch that makes log_warn / log_error
#                  record (plan 5.2); default on. After I5 there is no switch
#                  and "on" is the only behaviour.
# summary unset    AITOOLS_SUMMARY_FILE is unset for the case. Default: set
#                  to a new empty file {CASEDIR}/summary.txt
# env NAME=VALUE   set for the case process and its children
# stdin pty TEXT   (with "needs pty") run under a terminal; TEXT, then a newline,
#                  is typed at the first prompt
#
# Steps, run in file order:
# record LINE      append LINE to the run summary file as it is (input of a
#                  renderer case)
# file NAME|TEXT   write TEXT to {CASEDIR}/NAME
# call HELPER|ARG|...   call a library helper (table below) with ARGs.
#                  {CASEDIR} in an ARG is the case directory (native form);
#                  {RESULT} is the last deploy_managed_file result
# child NAME ACTION [REST]   one line of a child script NAME (below)
# relay LABEL|TOOL|CHILD[|abort-warn]          run child CHILD through the relay
# relay-native LABEL|TOOL|CHILD[|abort-warn]   run child CHILD as a separate process
#                  An empty TOOL means no summary tool is given. The optional
#                  4th field "abort-warn" is the runner's request that a user
#                  abort (exit 2) of this child be recorded by the relay as one
#                  warning under TOOL, "aborted by user" (deploy-harness):
#                  one warning of the parent and no error. Without it, an
#                  abort is a failed child: one error. The relay records an
#                  abort; the runner never records it as well.
# render           draw the panel from the run summary file
#
# Helpers (the notation uses the bash names):
#   notation               bash                      PowerShell
#   log                    log                       Log
#   log_warn               log_warn                  LogWarn
#   log_error              log_error                 LogError
#   write_warn             write_warn                Write-AitWarn
#   write_action           write_action              Write-AitAction
#   write_error            write_error               Write-AitError
#   error_reason OUT|CODE  error_reason OUT CODE     Get-AitErrorReason -Output OUT -ExitCode CODE
#                          (the reason on stdout)    (the reason returned)
#   write_summary          write_summary             Write-Summary
#   managed_abort          _managed_abort            Invoke-ManagedAbort
#   deploy_tracker_init    deploy_tracker_init       Initialize-DeployTracker
#   deploy_managed_file SRC|DEST|TOOL|ITEM
#                          deploy_managed_file SRC DEST TOOL ITEM;
#                          result MANAGED_FILE_RESULT
#                                                    Deploy-ManagedFile -Content SRC -DestPath DEST
#                                                    -ToolName TOOL -ItemName ITEM; result = its return value
#   deploy_tracker_record  deploy_tracker_record     Record-DeployOutcome -Outcome -ToolName -ItemName
#   deploy_tracker_summary deploy_tracker_summary    Write-DeployTrackerSummary -ToolName
#   render                 show_summary              Show-Summary
#   relay                  run_child_relayed [--summary-tool TOOL] LABEL bash {CASEDIR}/CHILD.sh
#                                                    Invoke-ChildRelayed LABEL {CASEDIR}/CHILD.ps1 @{} TOOL
#                                                    (in-process)
#   relay-native           (as relay)                Invoke-NativeRelayed: LABEL, TOOL and the command
#                                                    pwsh -NoProfile -File {CASEDIR}/CHILD.ps1
#                                                    (argument order as I1 defines it)
#   abort-warn             the relay's option for the runner's abort-as-warning
#                          request, in both languages, as I1 names it
#
# Child scripts. The harness writes {CASEDIR}/CHILD.sh or CHILD.ps1: the
# library loaded, logging_init CHILD / Initialize-Logging CHILD (so the
# child's script name is CHILD), then its action lines in order, then
# "exit N" (default exit 0). The child inherits the run summary file, the
# log directory and the switch. Actions:
#   call HELPER|ARG|...    as the step "call"
#   stdout TEXT            bash: printf '%s\n' TEXT   PowerShell: Write-Host TEXT
#   stderr TEXT            bash: printf '%s\n' TEXT >&2 (bash children only)
#   throw TEXT             PowerShell: throw TEXT (in-process children only)
#   write-error TEXT       PowerShell: Write-Error TEXT (default
#                          ErrorActionPreference, so the child goes on)
#   exit N                 the child's exit code
#
# ---------------------------------------------------------------------------
# EXPECTATIONS (checked after the steps)
# ---------------------------------------------------------------------------
# expect record LINE      the run summary file holds exactly the "expect
#                         record" lines of the case, in this order, one per
#                         line (compare the file without its final newline)
# expect no-records       the run summary file is empty
# expect record-count N PREFIX   exactly N records start with PREFIX
# expect count warnings N the script's warning count (WARNINGS / $script:warnings)
# expect count errors N   the script's error count (ERRORS / $script:errors)
# expect log TEXT         deploy.log has a line "[<utc-Z>] TEXT" (the
#                         timestamp removed, the rest equal)
# expect logsub LEVEL TEXT   deploy.log has a line at LEVEL whose message
#                         contains TEXT
# expect reason TEXT      the value of the last error_reason call
# expect result TEXT      the last deploy_managed_file result
# expect relay-rc N       the return value of the last relay call (0 or 1)
# expect child-rc N       AITLIB_CHILD_RC / $script:AitLibChildRc after it
# expect case-exit N      the case process, with "exit 0" appended to its
#                         steps, under set -euo pipefail /
#                         $ErrorActionPreference = "Stop", exits N
# expect panel-none       render printed nothing
# panel blank             a panel line: empty
# panel rule              a panel line: the rule (bash: U+2500 x 56;
#                         PowerShell: "-" x 60)
# panel COLOUR TEXT       a panel line: TEXT in COLOUR, one of green, yellow,
#                         red, magenta. bash: the line's ANSI colour (32, 33,
#                         31, 1;35), compared after every CSI sequence is
#                         removed; PowerShell: Write-Host -ForegroundColor
#                         (Green, Yellow, Red, Magenta)
# The "panel" lines of a case are the whole render output, in order.
# ---------------------------------------------------------------------------
